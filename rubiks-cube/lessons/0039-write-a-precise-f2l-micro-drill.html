Rubik’s Cube · under 10 minutes

Write a precise F2L micro-drill

Turn one three-log result into a bounded next practice plan—before making another turn.

The one thing to learn

Lesson 38 told you whether a drill’s earliest mismatch stayed put, moved later, or disappeared. Your next win is to make that verdict actionable: write one drill specification with a condition, a five-rep boundary, an observation checkpoint, and a retain/change rule.

Rule: target the current earliest mismatch only. A later mismatch is useful evidence, but it is not permission to practise everything at once.

The four-part specification

Condition
Same target pair and the same type of empty working slot as the comparable logs; name the earliest mismatch.
Five reps
Practise only the stage that fails: planning, green-light recognition, or authorized-trigger execution.
Checkpoint
Stop at the exact boundary that tests that stage—before destination positions, at the two-part green light, or just after the trigger.
Decision rule
Make one fresh comparable attempt. Retain the drill only if its first mismatch disappears or moves later; otherwise change one thing or slow down.

Worked example: a later mismatch

Baseline A and B both first failed at planning: the named U setup missed UFR + UF. Check C reached those positions, then failed because the corner’s white sticker faced Up.

Condition
Same blue-red pair; empty front-right slot; first mismatch is now the white-direction check.
Five reps
Read the pair → name corner white direction → choose side. Do not append an insertion trigger.
Checkpoint
At UFR + UF, say “white Right / Left / Up” before any trigger.
Decision rule
Fresh comparable attempt: retain if the first mismatch is later or absent; if White-Up remains first, slow the orientation read and keep this narrow drill.

This respects the recovery goal: the drill changes one decision while protecting solved pairs and avoiding speculative triggers.

Build yours in 90 seconds

  1. Copy the earliest mismatch from Check C (or the unchanged baseline label).
  2. State the comparable condition: target pair + empty working-slot type.
  3. Choose one checkpoint that occurs before the next stage.
  4. Write “five reps, then one fresh comparable log.”
  5. Write the honest criterion: later/none = retain; same earliest mismatch = change or slow.
Copyable template

Condition: [pair] + [empty slot]; earliest mismatch: [label].
Five reps: practise [one stage] only.
Checkpoint: stop at [specific observable state].

Decision: later/none → retain; same → change one thing or slow down.

Today’s tangible win

Write and run one four-line specification on a real or virtual cube. At the end, you will have a defensible next practice decision—not a vague intention to “work on F2L.”
