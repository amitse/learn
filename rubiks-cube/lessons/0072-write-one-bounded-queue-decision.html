Rubik's Cube · Lesson 72 · under 10 minutes

Write one bounded queue decision

Turn a valid F2L checkpoint observation into exactly one permitted next action—without inventing a cause or silently changing the practice condition.

Today’s one skill

Write a decision from evidence, not from a story. A valid checkpoint log tells you what was visible. The source row tells you what action is permitted. Your queue decision joins those two facts and stops.

Start with these two inputs

ACT source row
Approved action: run five slow green-light reads.
Scope: blue-red pair · front-right empty slot · say “white right; edge matches front centre” before trigger · checkpoint immediately before trigger.
VALID CHECKPOINT LOG
Rep 4 — immediately before trigger: front-right slot empty; corner white faces Right; matching edge’s front sticker matches the front centre.

The observation is literal and the four fields match. It is now usable evidence. It does not prove why a previous attempt missed or authorize a different drill.

The one-line shape

Because [literal valid observation], [copy one permitted action].

Because Rep 4 reached the checkpoint with white facing Right and the edge matching the front centre, run five slow green-light reads for the blue-red pair in a front-right empty slot, saying the cue before trigger.

This is bounded: the evidence stays literal; the action is copied from the ACT row; the carried condition remains visible; and no second action appears.

Three checks before you queue it

1
Evidence: quote only what the valid checkpoint log visibly says. Do not add “because I rushed” or “the grip was wrong.”
2
Permission: use the action from the selected ACT row. A valid log is evidence, not a menu of new actions.
3
Boundary: name one action only. Keep the pair, workspace, cue timing, and checkpoint fixed for that action.

Spot the unbounded version

Bad: “Because the pair looked ready, run five green-light reads, then insert it faster to fix the bad grip.”
  • “looked ready” weakens the literal observation;
  • “bad grip” invents a cause; and
  • “then insert it faster” adds a second action.

Repair it by deleting the unsupported material—not by explaining more.

Quick check

The same ACT source row and valid Rep 4 log above are selected. Which is a valid bounded queue decision?

Do it now

Take one valid checkpoint log from Lesson 71. Put its source ACT row beside it, then write one sentence using this frame:

Because [literal checkpoint observation], [one copied ACT action] under [the same four fields].

Read it once for an added cause and once for a second verb. If either appears, delete it. Ask your teacher to audit your sentence if you are unsure whether an action is copied or newly invented.
