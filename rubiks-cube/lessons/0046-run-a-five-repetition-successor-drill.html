Rubik’s Cube · under 10 minutes

Run a five-repetition successor drill

Keep a passed F2L drill fixed long enough to collect clean checkpoint evidence—then stop before you interpret it.

The one thing to learn

A five-repetition run is five identical attempts at one already-audited F2L drill. On every attempt, use the same pair, workspace, retained cue, trigger, and one checkpoint. Record the visible checkpoint result immediately; do not change the drill in response to an individual miss.

Run rule: execute → inspect at the stated checkpoint → log one observable result. Repeat five times. Fresh E/F come after the run, so today’s five rows are evidence—not a verdict.

Freeze the specification

Use your own audited successor plan. Here is a concrete execution-stage example from Lesson 45:

Fixed condition
Pair: blue-red
Workspace: empty front-right slot
Retained cue: “front sticker, front centre”
Fixed action + observation
Trigger: R U R′
Checkpoint: immediately after the trigger
Observable: “pair is / is not correctly placed in the front-right slot”

This is a drill example, not a claim that R U R′ solves every F2L case. Your audited plan determines its own authorized action and checkpoint.

Run it without contaminating it

  1. Read the fixed specification once. Do not add a second cue, new setup, or speed goal.
  2. Set up the identical kind of attempt and say the retained cue.
  3. Perform only the authorized trigger.
  4. At once, look at the stated checkpoint and write what is visible—not why it happened.
  5. Reset and repeat until five rows are complete. A miss is a row of data, not a reason to modify rep 2–5.

If you lose the fixed condition or cannot see the checkpoint, mark that row “invalid” and restart a fresh five-repetition run. Do not silently treat an unlike attempt as comparable.

Use a physical or virtual cube. For each row, record a fact at the one checkpoint. For the example, write placed, not placed, or invalid.
