Audit one F2L read-to-insert attempt

Turn one real attempt into useful evidence. The win is not necessarily an insertion—it is knowing which decision failed without disturbing solved pairs.

Mission connection. A repeatable solve requires recovery without a restart. A tiny audit separates a bad plan from a failed green light or a physical execution slip, so the next attempt changes one thing rather than becoming guesswork.

The one concept: an observation log

After attempting one basic F2L pair, record the first point where reality differed from your plan. Do this only for a pair with an empty working slot; protect all completed pairs.

1Plan: name the pair, its centre-defined slot, working side, and one setup (0, U, U2, or U′).
2Check: after setup, inspect positions plus both green-light checks: white faces the selected side; the UF edge’s front sticker matches the front centre.
3Act once: insert only if authorized. Otherwise stop or take the previously learned least-disruptive recovery.
4Audit: label the first mismatch below.

Five-minute cube drill

  1. Choose one unsolved F2L pair and place its empty slot at the working side.
  2. Say aloud: “pair ___; slot ___; side ___; setup ___.”
  3. Make only that setup. Run the two-part green light.
  4. Insert once only if both checks pass. Otherwise use one bounded recovery and re-read.
  5. Write one line: plan → observed → label → one change. Example: right/U → UFR+UF, white up → green-light failure → normalize once.

Stop after one logged attempt. Accuracy of the label matters more than finishing another pair.

Instant check

Scenario: You correctly named U′. After it, the target pair is at UFR + UF, but the corner’s white sticker faces Up. What is the best audit label and immediate response?
