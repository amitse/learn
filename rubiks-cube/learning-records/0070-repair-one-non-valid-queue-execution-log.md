# 0070 — Repair One Non-Valid Queue-Execution Log

**Date:** 2026-11-01  
**Lesson:** `0070-repair-one-non-valid-queue-execution-log.html`

## What was taught

- A non-valid F2L queue-execution log is repaired by locating its first failure: a changed scope field or an added cause, verdict, or follow-up action.
- A text repair changes only the mistaken written clause while retaining all matching scope and the literal cube observation.
- If the physical cube attempt actually changed pair, workspace, cue/timing, or checkpoint, it is drifted evidence and needs a new matching attempt; relabelling it cannot repair history.

## Key non-obvious insights

- A repaired log must never improve or reinterpret the observation just to make the attempt look useful.
- “Immediately before trigger” is a factual timing claim, not formatting; it can be corrected only when the actual observation was made there.
- Deleting an unbounded conclusion preserves a valid observation, but it does not authorize the deleted next action.
