# 0071 — Classify One Repaired Queue-Execution Log

**Date:** 2026-11-02  
**Lesson:** `0071-classify-one-repaired-queue-execution-log.html`

## What was taught

- A repaired F2L queue-execution log is valid only when its target pair, empty-workspace type, retained cue/timing, and checkpoint match the source instruction and it ends at a literal observation.
- A physical scope drift remains **REPLACEMENT EVIDENCE NEEDED** even if a text repair makes the written line look compliant.
- Classification is performed before a repaired log influences a drill, verdict, or next queue instruction.

## Key non-obvious insights

- Cue timing is evidence: speaking the same cue after setup is not equivalent to using it before setup.
- Deleting an unbounded conclusion can preserve an otherwise valid checkpoint log, but cannot create a fact that was not observed.
- A valid checkpoint log is evidence only; it does not itself authorize a new action or explain the result.
