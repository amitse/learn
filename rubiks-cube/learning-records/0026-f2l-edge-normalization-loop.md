# 0026 — F2L: Normalize an Unready Edge

**Date:** 2026-08-04  
**Lesson:** `0026-f2l-edge-normalization-loop.html`

## What was taught

- An F2L edge can be the correct matching partner while failing the front-centre readiness check at `UF`; pair identity and current readiness are different facts.
- The controlled **normalization loop** for an unready edge: name the pair → protect an empty front-right working slot → apply `R U R′` once → stop and re-read → use only U-layer setup turns to seek a verified picture.
- In a normalization attempt, `R U R′` is not assumed to insert a pair. Its purpose is to make one controlled change to an awkward corner–edge relationship.
- Insertion remains conditional on the existing two-part green light: corner white direction plus matching edge’s front sticker agreeing with the front centre.

## Key non-obvious insights

- A trigger has no inherent single “job”; the state at which it begins determines whether it inserts, ejects, or changes a relationship for inspection.
- The mandatory stop after one normalization trigger prevents a recovery technique from becoming an uncontrolled loop.
- If the re-read does not yield a safe picture, choosing another unsolved pair is a correct decision. Protecting solved F2L slots takes priority over forcing one pair.
