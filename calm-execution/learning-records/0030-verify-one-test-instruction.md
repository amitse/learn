# Learning Record 0030 — Verify One Test Instruction

## Date
2026-08-19

## Lesson
0030 — Verify One Test Instruction

## What was taught

- The learner compares one written bounded-test instruction with one actual attempt before interpreting an outcome.
- The record is read in a fixed order: `test used?`, `cue occurred?`, then `two-minute action started?`.
- An unused or unclear test is labelled `incomplete`, not treated as evidence that the test failed.
- A used test is retained unchanged while the learner gathers the next ordinary record; no redesign, compensation, or extra duration is added.

## Key insight

A result belongs to a test only when the named change happened: **confirm the exact instruction was used, then read cue and start.**

## Zone of proximal development notes

The learner has a carry-forward ritual, a stability boundary, test specification, fidelity reading, and a four-record re-triage, but actual evidence remains unknown. This is a focused fidelity refresh rather than a new system component. Preserve the two-minute baseline, chosen frequency, no-penalty stance, and one-variable approach. Do not add catch-up work, duration targets, multiple changes, or a larger tracking system.

## What comes next

After one or two ordinary attempts with the same clear instruction, teach a compact comparison of two used test records: retain a readable, non-frictional test; return only for clear added friction; otherwise gather ordinary evidence without changing another link.
