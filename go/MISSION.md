# Mission: Go (Golang)

## Why
I'm proficient in JavaScript/TypeScript and want to build an HTTP server in Go.
The goal is to be productive in Go fast — reading, writing, and shipping real Go code —
not a full language tour. TypeScript is my mental model; lessons should map Go concepts
to TS equivalents where helpful.

## Success looks like
- Can write a working HTTP server in Go from scratch (routes, handlers, JSON responses)
- Understands Go's type system well enough to not fight the compiler
- Can read Go code in the wild without constantly Googling syntax
- Knows when Go is doing something fundamentally different from JS/TS (goroutines, interfaces, error handling)
- Can `go build` and ship a binary

## Constraints
- Already knows: variables, functions, types, async/await, modules, REST APIs (from TS)
- Short daily lessons — one focused concept per session
- Prefers seeing TS → Go side-by-side comparisons where relevant
- Interactive lessons in the browser

## Out of scope
- Full language mastery (generics deep-dives, reflection, cgo, assembly)
- ORMs, databases — after the HTTP server is working
- Goroutines and channels beyond what's needed for an HTTP server
- Deployment/containerisation — after the server is built
