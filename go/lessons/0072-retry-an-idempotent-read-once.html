Retry an idempotent read once

Last lesson classified a dependency error. Now turn that decision into exactly one extra attempt—only for an operation you have explicitly decided is safe to repeat.

Tangible win: write a bounded retry wrapper that makes at most two attempts, immediately returns cancellation/deadline errors, and is trivial to test without sleeping.

Put the safety decision in the call site

A retry can duplicate work. A profile lookup is a reasonable teaching example because it is a read; a payment-creating POST is not automatically safe just because its transport error looked transient. The wrapper below does not infer HTTP method or business safety—it receives an already-approved operation.

type Profile struct { ID string `json:"id"` }

type getProfile func(context.Context, string) (Profile, error)

func getProfileWithOneRetry(ctx context.Context, id string, get getProfile) (Profile, error) {
    profile, err := get(ctx, id) // attempt 1
    if err == nil || !retryableDependencyError(err) {
        return profile, err
    }

    return get(ctx, id) // attempt 2 — bounded: no third call
}
Boundary: use the same context for both attempts. If the caller canceled or the deadline expired, lesson 71’s classifier returns false, so no extra work starts.

TypeScript mental model

TypeScript / Node

async function getWithOneRetry(id: string) {
  try {
    return await getProfile(id); // attempt 1
  } catch (err) {
    if (!retryable(err)) throw err;
    return getProfile(id);       // attempt 2
  }
}

Go

func getWithOneRetry(
  ctx context.Context, id string, get getProfile,
) (Profile, error) {
  p, err := get(ctx, id)
  if err == nil || !retryableDependencyError(err) {
    return p, err
  }
  return get(ctx, id)
}

Both versions make the retry limit visible. In Go, returning the second result also means a second failure is returned as-is: no loop, no hidden third attempt, and no retry of a known stop signal.

Test the number of attempts, not elapsed time

Injecting the operation as a function is the test seam. This test simulates a transient first failure and a successful second result; it never needs a real server or time.Sleep.

func TestGetProfileWithOneRetry(t *testing.T) {
    calls := 0
    get := func(context.Context, string) (Profile, error) {
        calls++
        if calls == 1 {
            return Profile{}, errors.New("connection reset")
        }
        return Profile{ID: "42"}, nil
    }

    got, err := getProfileWithOneRetry(context.Background(), "42", get)
    if err != nil { t.Fatalf("unexpected error: %v", err) }
    if got.ID != "42" { t.Fatalf("ID = %q; want 42", got.ID) }
    if calls != 2 { t.Fatalf("calls = %d; want 2", calls) }
}

Add a second table-style case where get returns fmt.Errorf("get profile: %w", context.Canceled). Assert calls == 1. That protects the most important stop rule.

What this deliberately does not solve

  • No delay/backoff: an immediate second attempt is a small, testable control-flow step—not a production traffic policy.
  • No HTTP-status policy: a response is not a transport error; decide status handling explicitly at the adapter boundary.
  • No generic retry-all helper: idempotency and side effects belong to the operation owner.

Quick check

A profile lookup’s first attempt returns wrapped context.DeadlineExceeded. How many calls should the wrapper make?
