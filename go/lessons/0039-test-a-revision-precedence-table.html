Test a revision precedence table

Lesson 38 made the build-identity rule explicit: stamped revision → vcs.revision → none. Now lock that operational contract down with a table-driven test, including the easy-to-miss empty-string case.

Tangible win: write a test that proves a CI release SHA wins, optional build info is a fallback, and blank data never becomes a fake revision.

One concept: the table is the policy

TypeScript mental model

A test.each matrix makes every configuration-precedence case visible: inputs on the left, expected identity on the right.

Go

A slice of anonymous structs plus t.Run is the standard-library table-driven equivalent. Each row documents one contract outcome.

Do not test debug.ReadBuildInfo() itself here—that is Go runtime behavior. Test your pure selector. It receives ordinary inputs, has no environment or binary dependency, and should always choose exactly one honest result.

Write the focused test

Assume the selector from Lesson 38 accepts a small buildSetting slice. Add this in the same package as selectedRevision so an unexported selector stays unexported.

func TestSelectedRevision(t *testing.T) {
    tests := []struct {
        name     string
        stamped  string
        settings []buildSetting
        want     string
    }{
        {
            name:     "stamped revision wins over VCS setting",
            stamped:  "release-sha",
            settings: []buildSetting{{Key: "vcs.revision", Value: "other-sha"}},
            want:     "release-sha",
        },
        {
            name:     "falls back to non-empty VCS setting",
            stamped:  "none",
            settings: []buildSetting{{Key: "vcs.revision", Value: "toolchain-sha"}},
            want:     "toolchain-sha",
        },
        {
            name:     "blank VCS setting falls back honestly",
            stamped:  "none",
            settings: []buildSetting{{Key: "vcs.revision", Value: ""}},
            want:     "none",
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := selectedRevision(tt.stamped, tt.settings)
            if got != tt.want {
                t.Fatalf("selectedRevision() = %q, want %q", got, tt.want)
            }
        })
    }
}

t.Run gives failures a readable row name. t.Fatalf is appropriate because there is only one assertion per row; continuing that row after a failed result offers no extra information.

Why the blank row matters

vcs.revision identifies a revision only when it is non-empty. A test that covers merely “setting exists” can accidentally bless an empty value. This row preserves the contract: missing, unavailable, or blank optional metadata resolves to the local fallback none.

  1. Put the test beside the selector, in a file ending _test.go.
  2. Run go test ./....
  3. Temporarily remove s.Value != "" from the selector. The blank-row test should fail.
  4. Restore the guard and run the test again. The green result is evidence that your startup identity cannot silently become blank.
