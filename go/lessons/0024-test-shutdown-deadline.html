Test the graceful-shutdown deadline

You have proved both successful shutdown properties: active requests drain and new connections are refused. Now test the failure boundary: a handler that never finishes must make Shutdown return when its context expires.

Shutdown is bounded by its context

http.Server.Shutdown(ctx) closes listeners, then waits for active connections to become idle. It waits only while ctx is alive. If the deadline expires first, it returns ctx.Err()—normally context.DeadlineExceeded.

Node / TypeScript
const signal = AbortSignal.timeout(1000)
await server.close({ signal })
// reject if draining outlives signal
Go
ctx, cancel := context.WithTimeout(
    context.Background(), time.Second,
)
defer cancel()
err := srv.Shutdown(ctx)
// err == context.DeadlineExceeded
The important distinction: a deadline return means the server stopped accepting new connections, but your blocked handler may still be running. Treat it as an operational failure to investigate—not proof that every goroutine disappeared.

Coordinate the test; do not guess with sleeps

Use started to prove the request has entered the handler, and release to keep it active. The deadline is deliberately short only because the test controls the causal ordering first.

func TestShutdownDeadline(t *testing.T) {
    started := make(chan struct{})
    release := make(chan struct{})

    mux := http.NewServeMux()
    mux.HandleFunc("GET /slow", func(w http.ResponseWriter, r *http.Request) {
        close(started)
        <-release // deliberately outlives the shutdown deadline
        w.WriteHeader(http.StatusNoContent)
    })

    ln, err := net.Listen("tcp", "127.0.0.1:0")
    if err != nil { t.Fatal(err) }
    srv := &http.Server{Handler: mux}
    go func() { _ = srv.Serve(ln) }()
    t.Cleanup(func() { _ = srv.Close() })

    go func() { _, _ = http.Get("http://" + ln.Addr().String() + "/slow") }()
    <-started // fact: there is an active handler

    ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
    defer cancel()
    err = srv.Shutdown(ctx)
    if !errors.Is(err, context.DeadlineExceeded) {
        t.Fatalf("Shutdown error = %v, want deadline exceeded", err)
    }

    close(release) // cleanup the held handler
}

Read the proof

1The request enters /slow; <-started makes that fact observable.

2Shutdown closes the listener, then blocks because release remains open.

3The deadline fires. errors.Is checks the returned error by identity, preserving the wrapped-error habit from Lesson 8.

4Close release so the test does not leak its deliberately blocked handler.

Use context.WithTimeout, not a bare timer, because Shutdown accepts a context and can report its cancellation cause directly. See also the errors.Is contract.
