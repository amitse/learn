Log a structured failure
and preserve its cause

A server failure needs two audiences: an operator needs an observable structured event, while Go code needs the original cause still discoverable through errors.Is. You can satisfy both at the application boundary.

Tangible win: add one failure branch that logs a stable slog event and returns a wrapped error whose sentinel cause remains intact.

One concept: observability is not error semantics

TypeScript mental model

At top level, you might log logger.error({err}, "server failed") and rethrow new Error("run HTTP server", {cause: err}). The log is evidence; the cause chain preserves programmatic meaning.

Go

Call logger.Error with named attributes, then return fmt.Errorf("run HTTP server: %w", err). The attribute records the failure; %w keeps it available to errors.Is.

Do this where process policy already lives: just outside Run. Do not add lifecycle logging to request handlers, and do not replace the returned error with errors.New or formatted %v.

The narrow failure branch

func runApp(run func() error, logger *slog.Logger) error {
    if err := run(); err != nil {
        logger.Error("HTTP server stopped unexpectedly",
            slog.Any("error", err),
            slog.String("version", moduleVersion()),
            slog.String("revision", revisionForLog()),
        )
        return fmt.Errorf("run HTTP server: %w", err)
    }
    return nil
}

slog.Any("error", err) keeps the error value attached to the event (the text handler renders its message). The message stays stable for queries; version and revision identify the process, just as at startup. Crucially, logging does not consume, replace, or unwrap err.

Prove both contracts in one focused test

func TestRunAppLogsFailureAndPreservesCause(t *testing.T) {
    sentinel := errors.New("listener accept failed")
    var out bytes.Buffer
    logger := slog.New(slog.NewTextHandler(&out, nil))

    err := runApp(func() error { return sentinel }, logger)

    if !errors.Is(err, sentinel) {
        t.Fatalf("returned error does not preserve cause: %v", err)
    }
    got := out.String()
    for _, want := range []string{
        `level=ERROR`,
        `msg="HTTP server stopped unexpectedly"`,
        `error="listener accept failed"`,
    } {
        if !strings.Contains(got, want) {
            t.Errorf("log missing %q:\n%s", want, got)
        }
    }
}

This is intentionally one test at one boundary: it supplies a deterministic failure, checks the returned error chain, then checks the log’s level, message, and failure field. It does not open a port or re-test revision precedence.

  1. Make a sentinel failure with errors.New.
  2. Inject a buffer-backed *slog.Logger.
  3. Log a stable error event with slog.Any("error", err).
  4. Return fmt.Errorf(... %w ...) and require errors.Is(err, sentinel).
