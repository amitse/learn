Close resources after HTTP drains

Your server already stops admitting new requests and lets active handlers finish. Add one precise lifecycle rule: only then close the dependency those handlers use—such as a database pool.

One concept: cleanup has an order

Node / TypeScript
await closeServer() // waits for requests
await db.end()      // now release pool
Go
if err := Run(...); err != nil { ... }
pool.Close()        // now release pool
Why this order? An in-flight handler can still query the database while Shutdown is draining. Closing its pool first turns a graceful HTTP shutdown into a failure for work you explicitly chose to finish.

Make main the application lifecycle owner

Run owns the HTTP server's lifecycle. The process edge owns dependencies around it: construct them before serving and close them after Run has returned. With defer, Go makes that cleanup rule visible next to acquisition.

func main() {
    ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
    defer stop()

    pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
    if err != nil { log.Fatal(err) }
    defer pool.Close() // runs only when main returns

    ln, err := net.Listen("tcp", ":8080")
    if err != nil { log.Fatal(err) }

    srv := &http.Server{Handler: routes(pool)}
    if err := Run(ctx, srv, ln, 10*time.Second); err != nil {
        log.Fatal(err)
    }
}

When the stop context is cancelled, Run closes admission, waits for active handlers (within its grace period), and returns. Only after that return does main return and run pool.Close().

Read the timeline, not just the code

SIGTERM / cancel
      │
      ▼
Run: close listener ──► reject new connections
      │
      ▼
Run: wait for active handlers ──► handler may still use pool
      │
      ▼
Run returns
      │
      ▼
defer pool.Close() ──► release database connections

1Acquire the pool before constructing handlers that depend on it.

2Keep the pool alive while Run drains.

3Return from main; deferred cleanup releases the pool.

Do not reverse it

// Wrong: a draining request can fail here.
stop()
pool.Close()
err := Run(ctx, srv, ln, grace)

// Right: Run finishes the HTTP contract first.
err := Run(ctx, srv, ln, grace)
pool.Close()

This lesson is about ordering, not a new shutdown mechanism. Keep connection-pool construction and close semantics in the application boundary; handlers should receive the already-live dependency.
