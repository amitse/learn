Log a request-ID generator failure privately

Lesson 61 proved a failed ID generator returns a safe JSON 500 and stops the handler chain. Now make that failure diagnosable without changing the HTTP response: emit one structured server-side error event containing the private cause.

Tangible win: a focused test decodes one captured slog event and proves the failure is observable while the client still sees only the generic 500.

The one idea: two outputs, two audiences

On this branch, the middleware has two jobs. The client gets the stable contract from Lesson 55. Operators get a stable event name plus the original error as a named attribute. Do not put error text in the event message, and never serialize it into the response.

Put the event at the failure boundary

Inject a logger; do not use the global default. It keeps middleware testable and lets the application choose JSON, level, and destination. A nil logger should have an explicit policy; the simplest is to require a non-nil logger when constructing production middleware.
func RequestID(next http.Handler, makeID IDGenerator,
    logger *slog.Logger) http.Handler {
  return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    id, err := makeID()
    if err != nil {
      logger.Error("request ID generation failed", "error", err)
      writeJSONError(w, http.StatusInternalServerError,
        "internal server error")
      return
    }
    // set header/context, then next.ServeHTTP(w, r)
    _ = id
  })
}
Capture one JSON record. A buffer-backed slog.NewJSONHandler is an in-process log sink. Give the generator a distinctive cause so the test can prove where that detail belongs.
var logs bytes.Buffer
logger := slog.New(slog.NewJSONHandler(&logs, nil))
privateErr := errors.New("entropy device unavailable")
makeID := func() (string, error) { return "", privateErr }
Decode only your event contract. Assert the stable message, ERROR level, and named error field. Independently decode the response and require the generic public text. Do not assert timestamps, key order, or every field emitted by slog.
type logEvent struct {
    Level string `json:"level"`
    Msg   string `json:"msg"`
    Error string `json:"error"`
}

func TestRequestIDFailureLogsPrivateCause(t *testing.T) {
    var logs bytes.Buffer
    logger := slog.New(slog.NewJSONHandler(&logs, nil))
    privateErr := errors.New("entropy device unavailable")
    makeID := func() (string, error) { return "", privateErr }

    w := httptest.NewRecorder()
    RequestID(http.NotFoundHandler(), makeID, logger).ServeHTTP(w,
        httptest.NewRequest(http.MethodGet, "/", nil))

    var event logEvent
    if err := json.Unmarshal(bytes.TrimSpace(logs.Bytes()), &event); err != nil {
        t.Fatal(err)
    }
    if event.Level != "ERROR" || event.Msg != "request ID generation failed" {
        t.Errorf("event = %#v", event)
    }
    if event.Error != privateErr.Error() {
        t.Errorf("logged error = %q", event.Error)
    }
    if strings.Contains(w.Body.String(), privateErr.Error()) {
        t.Error("private cause leaked to client")
    }
}

Why test the response again?

The log and the response are separate contracts. A logging change can accidentally tempt someone to reuse err.Error() as the JSON message. Keeping the no-leak assertion beside the decoded log event proves the intended split: rich private evidence, minimal public disclosure.

Scope rule: this event has no request ID attribute—generation failed before one existed. Do not invent a fallback correlation ID merely to fill the field. If you need to correlate infrastructure events, use an independent operational mechanism rather than claiming a request ID was issued.
