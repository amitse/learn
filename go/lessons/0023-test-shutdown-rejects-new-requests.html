Test shutdown rejects new requests

Lesson 22 proved that shutdown drains an in-flight request. The other half of the contract is equally important: once shutdown closes the listener, a new connection must not reach a handler.

The two phases of graceful shutdown

Server.Shutdown closes open listeners first, then waits for active connections to become idle. That gives your server a clean boundary: requests already inside may finish; new connections are refused.

Node / TypeScript
server.close(() => {
  // no longer accepting connections
});
// Existing requests may complete.
Go
go srv.Shutdown(ctx)
// listener closes first
// active handlers then drain

Do not test this by sleeping after Shutdown. Scheduling is not a contract. Instead, wrap the listener and signal exactly when its Close method is called.

Make listener closure observable

type signalListener struct {
    net.Listener
    closed chan struct{}
    once   sync.Once
}

func (l *signalListener) Close() error {
    l.once.Do(func() { close(l.closed) })
    return l.Listener.Close()
}

The embedded net.Listener supplies the usual listener methods. This tiny test wrapper overrides only Close. sync.Once makes the close signal safe even if cleanup closes the listener again.

The test: drain one request, reject the next

func TestShutdownRejectsNewRequests(t *testing.T) {
    raw, err := net.Listen("tcp", "127.0.0.1:0")
    if err != nil { t.Fatal(err) }
    ln := &signalListener{Listener: raw, closed: make(chan struct{})}

    started, release := make(chan struct{}), make(chan struct{})
    mux := http.NewServeMux()
    mux.HandleFunc("GET /slow", func(w http.ResponseWriter, r *http.Request) {
        close(started)
        <-release
        w.WriteHeader(http.StatusNoContent)
    })
    srv := &http.Server{Handler: mux}
    go func() { _ = srv.Serve(ln) }()
    t.Cleanup(func() { _ = srv.Close() })

    go func() { _, _ = http.Get("http://" + ln.Addr().String() + "/slow") }()
    <-started // an active request keeps Shutdown waiting

    shutdownDone := make(chan error, 1)
    go func() { shutdownDone <- srv.Shutdown(context.Background()) }()
    <-ln.closed // fact: Shutdown has closed the listener

    client := &http.Client{Transport: &http.Transport{DisableKeepAlives: true}}
    _, err = client.Get("http://" + ln.Addr().String() + "/new")
    if err == nil {
        t.Fatal("new request succeeded after listener closed")
    }

    close(release)
    if err := <-shutdownDone; err != nil { t.Fatalf("Shutdown: %v", err) }
}
Why a fresh client? A default HTTP transport can reuse an existing idle connection. DisableKeepAlives: true forces this assertion to require a new TCP connection—the thing a closed listener rejects.

Read the proof

1Start /slow and wait for started, so shutdown cannot finish immediately.

2Start Shutdown, then wait for <-ln.closed. This establishes the listener-close ordering without guessing a duration.

3A separate no-keep-alive client tries /new. It must receive a connection error, not an HTTP response.

4Release the old handler and require Shutdown to return successfully.

See the standard library documentation for shutdown ordering, net.Listener, and DisableKeepAlives.
