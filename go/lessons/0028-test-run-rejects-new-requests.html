Test Run rejects new requests

Lesson 27 proved that Run drains an active request. Now prove the complementary public contract: once cancellation starts shutdown, an existing request may finish—but a new TCP connection cannot enter.

The boundary is listener closure

Node / TypeScript
server.close() // stop accepting connections
// existing request may finish

// Force a fresh connection before testing:
await fetch(url, { agent: freshAgent })
Go
srv.Shutdown(ctx) // closes listener first
// existing handler may finish

transport := &http.Transport{
  DisableKeepAlives: true,
}
One concept: test admission at the observable listener-close boundary—not immediately after cancel(). Cancellation asks Run to begin shutdown; the wrapped listener proves it has actually stopped accepting connections.

Make listener closure observable

type closeObservedListener struct {
    net.Listener
    closed chan struct{}
    once   sync.Once
}

func (l *closeObservedListener) Close() error {
    l.once.Do(func() { close(l.closed) })
    return l.Listener.Close()
}

This is a narrow test wrapper: embedding keeps the ordinary net.Listener methods, while overriding Close adds one fact the test can wait for. sync.Once makes cleanup safe if the listener is closed again.

One deterministic test

func TestRunRejectsNewRequestsAfterCancel(t *testing.T) {
    started := make(chan struct{})
    release := make(chan struct{})
    srv := &http.Server{Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        close(started)
        <-release                         // keep first request active
        w.WriteHeader(http.StatusOK)
    })}

    raw, err := net.Listen("tcp", "127.0.0.1:0")
    if err != nil { t.Fatal(err) }
    ln := &closeObservedListener{raw, make(chan struct{}), sync.Once{}}
    t.Cleanup(func() { _ = ln.Close() })

    stop, cancel := context.WithCancel(context.Background())
    t.Cleanup(cancel)
    done := make(chan error, 1)
    go func() { done <- Run(stop, srv, ln, time.Second) }()

    addr := "http://" + ln.Addr().String()
    go func() { _, _ = http.Get(addr) }()
    <-started                             // request one is active

    cancel()
    <-ln.closed                           // listener is definitely closed

    client := &http.Client{Transport: &http.Transport{DisableKeepAlives: true}}
    if _, err := client.Get(addr); err == nil {
        t.Fatal("new request succeeded after shutdown began")
    }

    select {                               // active request still blocks Run
    case err := <-done:
        t.Fatalf("Run returned before drain: %v", err)
    default:
    }
    close(release)
    if err := <-done; err != nil { t.Fatalf("Run() = %v, want nil", err) }
}

1Hold request one in the handler, then cancel Run.

2Wait for ln.closed. This is the admission boundary, not a timing guess.

3Use a client that cannot reuse request one's connection. A successful request here is a real regression.

4Release request one and require the lifecycle owner to finish successfully.

Why force a fresh connection?

HTTP keep-alive can reuse an already-open connection. That would not test whether the closed listener rejects a new connection. DisableKeepAlives: true makes this request dial again, so failure is the expected result after listener closure. The active handler is deliberately retained to show that closed admission and graceful draining happen together.
