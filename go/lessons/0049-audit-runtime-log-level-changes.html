Audit runtime log-level changes

A shared slog.LevelVar can change live verbosity. That power needs a single, visible change boundary—not scattered Set calls that disappear precisely when they matter.

Tangible win

You will wrap the mutable level in one application-owned control, emit a structured log level changed audit event with from, to, and actor, and test it without a server or an HTTP admin endpoint.

The audit event must not use the level it changes

Suppose the application logger moves from INFO to WARN. If you set the threshold first and then write an INFO audit event through that same logger, the event is filtered out. An audit record must use a deliberately separate, durable sink whose policy is not controlled by the mutable application level.

TypeScript / Node

const appLog = createLogger({ level });
const auditLog = createLogger({ level: "info" });

function setLevel(actor: string, to: Level) {
  const from = level.current;
  level.current = to;
  auditLog.info({ actor, from, to },
    "log level changed");
}

Go

type LogLevelControl struct {
    level *slog.LevelVar
    audit *slog.Logger // fixed, separate policy
}

func (c *LogLevelControl) Set(
    ctx context.Context, actor string, to slog.Level,
) {
    from := c.level.Level()
    c.level.Set(to)
    c.audit.InfoContext(ctx, "log level changed",
        "actor", actor, "from", from, "to", to)
}
One owner: construct LogLevelControl once at the application boundary, with the same *slog.LevelVar used by the application handler. Future authenticated operations code calls control.Set; ordinary handlers receive neither the control nor the raw LevelVar.

Make the audit sink explicit

For this focused example, the audit logger is a JSON handler writing to a destination chosen by your application boundary. In a real service, agree with operations whether this is stdout, a separate durable stream, or an external audit system. The important local contract is that its minimum level remains capable of recording the change event.

func newLogLevelControl(out io.Writer, initial slog.Level) (*slog.Logger, *LogLevelControl) {
    var level slog.LevelVar
    level.Set(initial)

    app := slog.New(slog.NewJSONHandler(out,
        &slog.HandlerOptions{Level: &level}))

    audit := slog.New(slog.NewJSONHandler(out,
        &slog.HandlerOptions{Level: slog.LevelInfo}))

    return app, &LogLevelControl{level: &level, audit: audit}
}

This is intentionally not an HTTP endpoint. Authentication, authorization, input parsing, and durable retention are separate concerns. First give the live mutation one owner and a testable audit contract.

Concurrency boundary: LevelVar safely supports concurrent reads and Set calls. If your product requires a strict, ordered history of simultaneous changes, make the control operation serial (for example with a mutex) and send audit events to a system that preserves the ordering you need. Do not claim ordering that your sink cannot provide.

Test the facts an operator needs

Capture the audit JSON, perform one change, decode one record, and assert stable fields. Avoid asserting timestamps or a whole serialized line.

func TestLogLevelControlAuditsChange(t *testing.T) {
    var out bytes.Buffer
    _, control := newLogLevelControl(&out, slog.LevelInfo)

    control.Set(context.Background(), "on-call:amit", slog.LevelDebug)

    var event map[string]any
    if err := json.Unmarshal(bytes.TrimSpace(out.Bytes()), &event); err != nil {
        t.Fatal(err)
    }
    if event["msg"] != "log level changed" { t.Fatal("missing audit event") }
    if event["actor"] != "on-call:amit" { t.Fatal("wrong actor") }
    if event["from"] != "INFO" || event["to"] != "DEBUG" {
        t.Fatalf("transition = %v → %v", event["from"], event["to"])
    }
}

slog.Level implements text marshaling, so JSON handler output represents the levels as strings such as INFO and DEBUG. The test checks the transition and actor, not incidental formatting.
