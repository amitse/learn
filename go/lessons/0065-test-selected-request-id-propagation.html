Test the selected request ID across outputs

Your middleware now chooses either a valid trusted upstream ID or a generated fallback. Prove that the one selected value—not the raw header—reaches both the client response and private error log.

Tangible win: write one focused test that catches an accidental leak of an invalid upstream ID into X-Request-ID or structured logs.

Test the decision, not the implementation

Lesson 64 table-tested the selector. This test exercises the middleware boundary: supply a trusted but invalid upstream header, force the next handler to fail, then compare two observable outputs. The raw value must appear in neither.

Why force an error? A normal response proves the header path. A deliberately failing downstream handler also causes your existing private error logging path to run, giving this single test two independent sinks to compare. The public JSON error must remain generic.

One end-to-end contract test

func TestInvalidTrustedUpstreamIDUsesGeneratedIDEverywhere(t *testing.T) {
    var logs bytes.Buffer
    logger := slog.New(slog.NewJSONHandler(&logs, nil))
    generate := func() (string, error) { return "generated-7", nil }

    next := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        logger.Error("request failed", "request_id", RequestID(r.Context()))
        writeJSONError(w, http.StatusInternalServerError, "internal server error")
    })
    h := RequestIDMiddleware(generate, logger)(next)

    req := httptest.NewRequest(http.MethodGet, "/boom", nil)
    req.Header.Set("X-Request-ID", "bad id")
    req = req.WithContext(withTrustedProxy(req.Context()))
    rr := httptest.NewRecorder()
    h.ServeHTTP(rr, req)

    if got := rr.Header().Get("X-Request-ID"); got != "generated-7" {
        t.Fatalf("X-Request-ID = %q; want generated fallback", got)
    }
    if strings.Contains(rr.Body.String(), "bad id") { t.Fatal("upstream ID leaked") }

    var event struct { RequestID string `json:"request_id"` }
    if err := json.Unmarshal(bytes.TrimSpace(logs.Bytes()), &event); err != nil { t.Fatal(err) }
    if event.RequestID != "generated-7" { t.Fatalf("log ID = %q", event.RequestID) }
}

Adapt names to your code. The essential shape is fixed: inject a deterministic generator and buffer-backed JSON logger; make a trusted malformed header; assert the selected fallback in every output you own.

Keep the assertions deliberately narrow

Assert the header exactly. It is the client-visible correlation contract.
Decode the event. Assert the owned request_id field, not timestamp, key ordering, or every logger field.
Check absence once. A distinctive invalid value being absent from the response guards against a later accidental echo. Do not assert unrelated log formatter details.

Quick check

A trusted proxy sends X-Request-ID: bad id; the generator returns generated-7. Which test expectation is correct?
