Add source locations to slog events

When an operator needs to jump from a lifecycle event to the line that emitted it, slog can include source metadata. You will enable it once at logger construction and test its presence without freezing a fragile file path or line number.

Tangible win

By the end, you can add AddSource: true to your JSON logger and verify that an emitted event contains source information while your stable message and identity fields remain unchanged.

Source is handler policy

slog.HandlerOptions{AddSource: true} tells a handler to include the source file and line of the logging call in each record it handles. It is useful when the people reading the logs can act on that location. Like your JSON format and INFO threshold, select it once where the application assembles its logger—not in handlers or at individual log calls.

TypeScript / Node mental model

// Configure the logger's caller metadata once
createLogger({
  format: json(),
  includeCaller: true,
})

logger.info("HTTP server starting")

Go

// Configure handler metadata once
opts := &slog.HandlerOptions{
    Level:     slog.LevelInfo,
    AddSource: true,
}
logger := slog.New(slog.NewJSONHandler(os.Stderr, opts))

logger.Info("HTTP server starting")
Keep the contract straight: source data helps a human investigate an event. Your stable message ("HTTP server starting") and queryable attributes (version, revision) still identify what happened. Source is supporting metadata, not an event name.

Make one deliberate construction change

func newLogger(out io.Writer) *slog.Logger {
    opts := &slog.HandlerOptions{
        Level:     slog.LevelInfo,
        AddSource: true,
    }
    return slog.New(slog.NewJSONHandler(out, opts))
}

This leaves call sites alone. A JSON record gains a source object containing dynamic location details, alongside fields such as time, level, and msg. Enable it only when that extra detail is useful to the log consumer; it adds work and makes output noisier.

Test presence, not a line number

Source location is intentionally tied to code layout. A refactor can change the path or line without changing your logging policy. Capture one JSON record, decode it, and assert that the source field exists and has the fields your consumer needs.

func TestLoggerAddsSource(t *testing.T) {
    var out bytes.Buffer
    logger := newLogger(&out)
    logger.Info("HTTP server starting")

    var got map[string]any
    if err := json.Unmarshal(out.Bytes(), &got); err != nil {
        t.Fatal(err)
    }

    source, ok := got["source"].(map[string]any)
    if !ok {
        t.Fatal("source object missing")
    }
    if source["function"] == "" || source["file"] == "" {
        t.Fatal("source location was incomplete")
    }
}

The exact JSON representation is owned by the handler, so do not assert a full serialized line. This test checks the behaviour you chose: source metadata is emitted. Keep your existing test for the INFO threshold separate; it already verifies which events reach the handler.
