JSON Request & Response

How to read JSON from a request body and write JSON back — the single most important skill for building a real API in Go. Covers encoding/json, struct tags, and the exact pattern you'll use in every handler.

The TypeScript Starting Point

In Express/TypeScript you lean on req.json() or the express.json() middleware, and JSON.stringify() on the way out. Go's standard library gives you explicit, type-safe encoding/decoding — no middleware magic, no any. The trade-off: a few extra lines, but the compiler guarantees the shape of your data.

TypeScript / Express
// Request body → typed object
interface CreateUser {
  name: string
  email: string
}

app.post('/users', (req, res) => {
  const body = req.body as CreateUser
  // body.name, body.email

  res.json({ id: 1, ...body })
})
Go
// Request body → typed struct
type CreateUser struct {
  Name  string `json:"name"`
  Email string `json:"email"`
}

func createUser(w http.ResponseWriter,
                r *http.Request) {
  var body CreateUser
  json.NewDecoder(r.Body).Decode(&body)
  // body.Name, body.Email

  w.Header().Set("Content-Type", "application/json")
  json.NewEncoder(w).Encode(body)
}

Struct Tags — The Secret Sauce

Go's struct tags are the key to JSON in Go. They're backtick strings attached to struct fields that tell encoding/json how to map field names to JSON keys. Without them, your JSON would have PascalCase keys like "Name" instead of "name". 

type User struct {
  ID        int    `json:"id"`           // → "id" in JSON
  Name      string `json:"name"`         // → "name" in JSON
  Email     string `json:"email"`        // → "email" in JSON
  AvatarURL string `json:"avatar_url,omitempty"` // omitted if empty
  Password  string `json:"-"`            // NEVER included in output
}
Key Insight Struct tags are the Go equivalent of TypeScript's field names in a type + a serializer like class-transformer. In Go, they're built into the language itself — no library needed. The backtick (`) is the raw string delimiter; the tag content is json:"keyname".

The Three Tag Patterns You'll Use 90% of the Time

Tag Effect TypeScript analogy
`json:"name"` Use "name" as the JSON key instead of the field name Rename via serializer / column alias
`json:"name,omitempty"` Skip the field if it's the zero value (empty string, 0, nil, false) Optional field: name?: string
`json:"-"` Never marshal/unmarshal this field @Exclude() or just omit from response type

Decoding a Request Body

To parse the JSON body of a POST/PUT request, use json.NewDecoder. The decoder wraps an io.Reader — and r.Body is one. 

func createUser(w http.ResponseWriter, r *http.Request) {
  var input CreateUser

  // Decode the JSON body into `input`
  if err := json.NewDecoder(r.Body).Decode(&input); err != nil {
    http.Error(w, "invalid JSON", http.StatusBadRequest)
    return
  }

  // input.Name and input.Email are now populated
  fmt.Println(input.Name, input.Email)
}
⚠ Always check the error Decode returns an error if the body is not valid JSON, or if fields can't be converted to the struct's types. If you ignore the error, your handler will silently use the zero values ("", 0, false) — a subtle bug that's hard to diagnose.

Why &input (the & pointer)?

Decode needs to write into your variable, not read from it. In Go, to let a function modify your variable, you pass a pointer to it with &. This is the same reason you see & in fmt.Scan(&x) — it's "give me the address so I can fill it in."

Encoding a Response

To write a JSON response, use json.NewEncoder. It wraps an io.Writer — and http.ResponseWriter is one. Always set the Content-Type header before writing the body. 

type UserResponse struct {
  ID    int    `json:"id"`
  Name  string `json:"name"`
  Email string `json:"email"`
}

func createUser(w http.ResponseWriter, r *http.Request) {
  var input CreateUser
  if err := json.NewDecoder(r.Body).Decode(&input); err != nil {
    http.Error(w, "invalid JSON", http.StatusBadRequest)
    return
  }

  // Build the response
  resp := UserResponse{ID: 1, Name: input.Name, Email: input.Email}

  // 1. Set Content-Type BEFORE writing body
  w.Header().Set("Content-Type", "application/json")

  // 2. Set status (optional — defaults to 200 if omitted)
  w.WriteHeader(http.StatusCreated) // 201

  // 3. Encode the struct as JSON directly into the response body
  json.NewEncoder(w).Encode(resp)
}
💡 Encoder vs Marshal json.NewEncoder(w).Encode(v) streams JSON directly to the writer — ideal for HTTP responses (zero copy). json.Marshal(v) returns []byte — useful when you need the raw bytes, e.g. to log or sign them. For HTTP handlers, always prefer the Encoder.

Putting It All Together

Here's a complete, runnable handler you can drop into any Go HTTP server from lessons 3–4. It registers at POST /users, reads JSON in, and writes JSON out. 

package main

import (
  "encoding/json"
  "net/http"
)

type CreateUserInput struct {
  Name  string `json:"name"`
  Email string `json:"email"`
}

type CreateUserResponse struct {
  ID    int    `json:"id"`
  Name  string `json:"name"`
  Email string `json:"email"`
}

func createUser(w http.ResponseWriter, r *http.Request) {
  var input CreateUserInput

  if err := json.NewDecoder(r.Body).Decode(&input); err != nil {
    http.Error(w, "bad request: "+err.Error(), http.StatusBadRequest)
    return
  }

  resp := CreateUserResponse{
    ID:    42,
    Name:  input.Name,
    Email: input.Email,
  }

  w.Header().Set("Content-Type", "application/json")
  w.WriteHeader(http.StatusCreated)
  json.NewEncoder(w).Encode(resp)
}

func main() {
  mux := http.NewServeMux()
  mux.HandleFunc("POST /users", createUser) // Go 1.22+
  http.ListenAndServe(":8080", mux)
}

Test it with curl:

curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Amit","email":"amit@example.com"}'

Common Mistakes

Mistake What happens Fix
Forgetting & in Decode Compile error: cannot use value as *T Always pass &yourVar
No struct tags JSON keys are PascalCase ("Name" not "name") Add `json:"name"` to every field
Set Content-Type after WriteHeader Header is silently ignored — client sees no Content-Type Always call w.Header().Set(...) first
Ignoring Decode error Handler proceeds with zero-value struct — silent bad data Always if err != nil { http.Error(...); return }
Using Marshal + w.Write for responses Works, but needs error handling for Write; encoder is simpler Prefer json.NewEncoder(w).Encode(v)
