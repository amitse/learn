Full Mini HTTP Server

Putting it all together — routing, JSON, middleware, and error handling in a single runnable Go binary.

What You'll Build

This lesson assembles everything from lessons 3–6 into one complete server. No new concepts — just integration. After this lesson you'll have a runnable pattern you can copy as the skeleton for any Go HTTP server.

The server exposes a tiny "users" API:

MethodPathWhat it does
GET /health Returns {"ok":true} — health-check endpoint
GET /users/{id} Returns a user by ID (stubbed), or 404 if id = "999"
POST /users Accepts a JSON body, validates it, returns 201 with the created user

All responses are JSON. A logging middleware wraps the whole mux. Errors use a shared helper so every error response looks the same.

Project Layout

For a server this small, one package is fine. Real projects split into sub-packages — but that comes later. Here's the structure:

myapi/
  go.mod— module declaration
  main.go— server wiring: mux, middleware, ListenAndServe
  handlers.go— handler functions (health, getUser, createUser)
  middleware.go— Logger middleware
  respond.go— shared JSON helpers: writeJSON, writeError
Why split files? In Go, all .go files in the same directory share the same package. Splitting into files is purely for human readability — there's no import needed between them.

Step 1 — Shared Respond Helpers

First, centralise JSON writing so handlers never manually set headers or call encoders:

// respond.go
package main

import (
    "encoding/json"
    "net/http"
)

func writeJSON(w http.ResponseWriter, status int, data any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(data)
}

type errResponse struct {
    Error string `json:"error"`
}

func writeError(w http.ResponseWriter, status int, msg string) {
    writeJSON(w, status, errResponse{Error: msg})
}
TypeScript / Express
// res.json() sets Content-Type automatically
res.status(400).json({ error: "bad input" })
Go
// helper does the same, explicitly
writeError(w, 400, "bad input")

Step 2 — Logging Middleware

// middleware.go
package main

import (
    "log"
    "net/http"
    "time"
)

func Logger(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        next.ServeHTTP(w, r)
        log.Printf("%s %s — %v", r.Method, r.URL.Path, time.Since(start))
    })
}

Nothing new here — the before/after pattern from lesson 6. It wraps the mux so every route is logged.

Step 3 — Handlers

// handlers.go
package main

import (
    "net/http"
)

// GET /health
func healthHandler(w http.ResponseWriter, r *http.Request) {
    writeJSON(w, http.StatusOK, map[string]bool{"ok": true})
}

type User struct {
    ID   string `json:"id"`
    Name string `json:"name"`
}

// GET /users/{id}
func getUserHandler(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")

    // Simulate a "not found" case
    if id == "999" {
        writeError(w, http.StatusNotFound, "user not found")
        return
    }

    user := User{ID: id, Name: "Alice"}
    writeJSON(w, http.StatusOK, user)
}

type CreateUserInput struct {
    Name string `json:"name"`
}

// POST /users
func createUserHandler(w http.ResponseWriter, r *http.Request) {
    var input CreateUserInput

    if err := json.NewDecoder(r.Body).Decode(&input); err != nil {
        writeError(w, http.StatusBadRequest, "invalid JSON")
        return
    }

    if input.Name == "" {
        writeError(w, http.StatusUnprocessableEntity, "name is required")
        return
    }

    created := User{ID: "42", Name: input.Name}
    writeJSON(w, http.StatusCreated, created)
}
The return after each error matters. Go handlers don't stop on writeError — execution continues unless you explicitly return. Forgetting the return is a very common bug: the error response is sent, then execution falls through and tries to write again, causing a "superfluous response.WriteHeader call" warning.

Step 4 — Wiring It Together in main.go

// main.go
package main

import (
    "log"
    "net/http"
)

func main() {
    mux := http.NewServeMux()

    mux.HandleFunc("GET /health",       healthHandler)
    mux.HandleFunc("GET /users/{id}",   getUserHandler)
    mux.HandleFunc("POST /users",        createUserHandler)

    // Wrap the entire mux in logging middleware
    handler := Logger(mux)

    log.Println("Listening on :8080")
    log.Fatal(http.ListenAndServe(":8080", handler))
}
Express (TypeScript)
import express from 'express'
const app = express()

app.use(express.json())
app.use(logger)   // global middleware

app.get('/health', healthHandler)
app.get('/users/:id', getUserHandler)
app.post('/users', createUserHandler)

app.listen(8080)
Go
mux := http.NewServeMux()

// no express.json() — decode per handler
// middleware wraps mux, not app.use()

mux.HandleFunc("GET /health", healthHandler)
mux.HandleFunc("GET /users/{id}", getUserHandler)
mux.HandleFunc("POST /users", createUserHandler)

handler := Logger(mux)
http.ListenAndServe(":8080", handler)

Running the Server

# From the myapi/ directory:
go run .

# In another terminal, test each route:
curl http://localhost:8080/health
# → {"ok":true}

curl http://localhost:8080/users/7
# → {"id":"7","name":"Alice"}

curl http://localhost:8080/users/999
# → {"error":"user not found"}

curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Bob"}'
# → {"id":"42","name":"Bob"}

curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{}'
# → {"error":"name is required"}
Build a static binary: go build -o myapi . produces a single self-contained executable. Copy it to any Linux server — no Node runtime, no package install, no Docker required.
