Emit lifecycle logs as JSON

Your server now emits structured startup, failure, and clean-stop events. Make those same fields machine-readable by swapping the slog.Handler at the application boundary—not by changing every log call.

Tangible win

By the end, you can configure a production JSON logger and write a focused test that checks the emitted JSON record without a real server.

One event, two representations

A slog.Logger sends a record (level, message, attributes) to its handler. TextHandler renders readable key/value text; JSONHandler renders one JSON object per record. The logging call—and therefore the stable message plus version/revision contract—stays the same.

TypeScript / Node mental model

// Same event object; select a JSON transport/formatter
logger.info({ version, revision }, "HTTP server starting")

Go

// Same record; select its renderer at construction
logger.Info("HTTP server starting",
  slog.String("version", version),
  slog.String("revision", revision),
)
Boundary rule: choose the handler once where main assembles operational dependencies. Request handlers receive a logger only if they have a distinct request-level logging need; they do not decide the process log format.

Change only the handler

package main

import (
    "log/slog"
    "os"
)

func main() {
    // One newline-delimited JSON object per log record.
    logger := slog.New(slog.NewJSONHandler(os.Stderr, nil))

    logger.Info("HTTP server starting",
        slog.String("version", version),
        slog.String("revision", revision),
    )
    // run(logger) ...
}

A typical line is conceptually:

{"time":"2026-09-06T07:00:00Z","level":"INFO","msg":"HTTP server starting","version":"v1.4.0","revision":"abc123"}

The dynamic time is useful operationally but brittle in a test. Assert the event facts you own: message, level, and identity fields. Do not compare the whole serialized string or hard-code a timestamp.

Test the JSON shape, not formatting

JSONHandler writes newline-delimited JSON (one object per record). Capture one record in a bytes.Buffer, decode it into a map, then inspect its fields.

func TestStartupEventIsJSON(t *testing.T) {
    var out bytes.Buffer
    logger := slog.New(slog.NewJSONHandler(&out, nil))

    logger.Info("HTTP server starting",
        slog.String("version", "v1.4.0"),
        slog.String("revision", "abc123"),
    )

    var got map[string]any
    if err := json.Unmarshal(out.Bytes(), &got); err != nil {
        t.Fatalf("decode log JSON: %v\n%s", err, out.String())
    }
    if got["msg"] != "HTTP server starting" { t.Fatalf("msg = %v", got["msg"]) }
    if got["level"] != "INFO" { t.Fatalf("level = %v", got["level"]) }
    if got["version"] != "v1.4.0" { t.Fatalf("version = %v", got["version"]) }
    if got["revision"] != "abc123" { t.Fatalf("revision = %v", got["revision"]) }
}

The standard package specifies that JSON handler output is a sequence of complete JSON objects separated by newlines, so this test is testing a supported representation—not an accidental byte layout.

Do this now

  1. At your application composition boundary, replace slog.NewTextHandler(os.Stderr, nil) with slog.NewJSONHandler(os.Stderr, nil).
  2. Keep the existing logger.Info/logger.Error calls and named identity attributes unchanged.
  3. Add the focused buffer-and-decode test above for one lifecycle event.
  4. Run go test ./.... If a log collector expects plain text, retain TextHandler; handler choice is a deployment integration decision, not a Go style rule.
