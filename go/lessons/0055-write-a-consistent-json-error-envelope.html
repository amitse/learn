Write a consistent JSON error envelope

Lesson 54 kept internal errors out of the response. Now make the client-facing part deliberate: every error from this API has one small JSON shape, while the server still logs the detailed cause privately.

Tangible win

You will define errorResponse and a tiny writeJSONError helper that emits {"error":"…"} with the correct HTTP status and Content-Type.

One public shape, many statuses

A status tells a client what class of result occurred; a predictable body gives it a stable value to display or branch on. Keep the public message intentional. An unexpected failure can say internal server error, never the value of err.Error().

SituationStatusPublic JSON
No verified identity401{"error":"unauthorized"}
Verified caller lacks permission403{"error":"forbidden"}
Unexpected control failure500{"error":"internal server error"}

TypeScript / Express

function sendError(res: Response,
  status: number, message: string) {
  res.status(status).json({ error: message });
}

sendError(res, 403, "forbidden");

Go / net/http

type errorResponse struct {
    Error string `json:"error"`
}

func writeJSONError(w http.ResponseWriter,
    status int, message string) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    _ = json.NewEncoder(w).Encode(errorResponse{Error: message})
}
The ordering is part of the contract. Set headers before WriteHeader. In net/http, writing the status commits the headers; encoding after that writes the response body.

Use it at the handler boundary

The handler still classifies errors. The helper only renders the selected public outcome, so it cannot accidentally turn every failure into a 403 or leak a private cause.

if err := control.Set(r.Context(), principal, level); err != nil {
    if errors.Is(err, ErrForbidden) {
        writeJSONError(w, http.StatusForbidden, "forbidden")
        return
    }
    logger.Error("log level change failed", "error", err)
    writeJSONError(w, http.StatusInternalServerError, "internal server error")
    return
}
w.WriteHeader(http.StatusNoContent)
Do not use this helper for 204. A 204 No Content response must not include a body. It remains a separate success branch with w.WriteHeader(http.StatusNoContent).

Make the contract executable

func TestWriteJSONError(t *testing.T) {
    w := httptest.NewRecorder()

    writeJSONError(w, http.StatusInternalServerError,
        "internal server error")

    if w.Code != http.StatusInternalServerError { t.Fatal(w.Code) }
    if got := w.Header().Get("Content-Type"); got != "application/json" {
        t.Fatalf("Content-Type = %q", got)
    }
    var body errorResponse
    if err := json.NewDecoder(w.Body).Decode(&body); err != nil { t.Fatal(err) }
    if body.Error != "internal server error" { t.Fatal(body.Error) }
}

For a production API, you may later choose a versioned or code-bearing error schema. Today, own only the smallest stable contract: one error field, correct media type, and no internal details.
