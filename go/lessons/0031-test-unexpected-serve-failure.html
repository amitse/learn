Test an unexpected
Serve failure

Graceful shutdown is success. A listener failure is not. Add one narrow, no-network test that proves your Run boundary preserves the difference—so process-edge code can log a genuine infrastructure failure.

Only intentional closure becomes nil

Lessons 25–30 established that Run normalizes http.ErrServerClosed after intentional shutdown. That rule must stay narrow. http.Server.Serve otherwise returns a non-nil error when its listener cannot accept connections. Preserve that error.

Node / TypeScript
try {
  await server.listen(port)
} catch (err) {
  // Do not turn EADDRINUSE
  // into a normal shutdown.
  throw err
}
Go
func normalServeResult(err error) error {
  if errors.Is(err, http.ErrServerClosed) {
    return nil // intentional stop
  }
  return err // infrastructure failure
}
Boundary policy: normalize the documented sentinel only. Returning every Serve error as nil hides a broken listener, permission problem, or other operational failure.

Make the failure deterministic with a listener seam

Serve needs a net.Listener. A tiny fake whose Accept immediately returns a sentinel error makes the failure synchronous and requires no port, sleep, or goroutine coordination.

var errAccept = errors.New("listener failed")

type failingListener struct{ err error }

func (l failingListener) Accept() (net.Conn, error) { return nil, l.err }
func (l failingListener) Close() error              { return nil }
func (l failingListener) Addr() net.Addr             { return fakeAddr("test") }

type fakeAddr string
func (a fakeAddr) Network() string { return string(a) }
func (a fakeAddr) String() string  { return string(a) }

This is a narrow fake, not a mock of the entire server: it implements just the three methods required by net.Listener. Since Accept fails immediately, Serve returns immediately too.

The focused test

func TestRunReturnsUnexpectedServeFailure(t *testing.T) {
    srv := &http.Server{Handler: http.NewServeMux()}

    err := Run(context.Background(), srv,
        failingListener{err: errAccept}, time.Second)

    if !errors.Is(err, errAccept) {
        t.Fatalf("Run() error = %v; want errAccept", err)
    }
}

Use errors.Is, not string comparison: it keeps the test correct if a lower layer wraps the sentinel. This tests the other side of your lifecycle contract without retesting cancellation, admission closure, or HTTP draining.

Trace the two outcomes

  1. Intentional stop: cancellation → Shutdown → Serve returns http.ErrServerClosed → Run returns nil.
  2. Unexpected listener failure: Accept returns errAccept → Serve returns it → Run returns an error.

Quick check

Choose an answer for instant feedback.

1. Which result should Run normalize to nil?

2. Why use failingListener?

3. Why assert errors.Is(err, errAccept)?

Ask your teacher: ask how to choose a process policy after this error—log and exit, or report it to a supervisor—without putting that policy inside Run.
