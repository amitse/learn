Structured startup identity with slog

Your server already chooses a truthful version and revision. Now emit those same facts as named fields, so humans and log tools can reliably find the exact binary that started.

Tangible win: replace one formatted startup line with a testable log/slog event carrying version and revision.

One concept: message vs. attributes

TypeScript mental model

Instead of interpolating facts into logger.info(`starting ${version}`), send a stable message and a structured object: logger.info({version, revision}, "HTTP server starting").

Go

slog separates the event message from its attributes. Use a stable message, then attach named slog.String attributes. A handler renders text or JSON later.

This belongs at the application boundary—not in a handler. Version and revision describe the process artifact, while a request handler describes one request. Keep the existing selectors from Lessons 37–39; only change presentation.

Emit one startup event

import (
    "log/slog"
    "os"
)

func runApp(run func() error, logger *slog.Logger) error {
    logger.Info("HTTP server starting",
        slog.String("version", moduleVersion()),
        slog.String("revision", revisionForLog()),
    )

    if err := run(); err != nil {
        return fmt.Errorf("run HTTP server: %w", err)
    }
    logger.Info("HTTP server stopped")
    return nil
}

func main() {
    logger := slog.New(slog.NewTextHandler(os.Stderr, nil))
    if err := runApp(Run, logger); err != nil {
        logger.Error("HTTP server failed", "error", err)
        os.Exit(1)
    }
}

Info receives a message followed by attributes. slog.String makes both the field name and its string type explicit. With NewTextHandler, a line will include fields like msg="HTTP server starting" version=dev revision=none; use NewJSONHandler when your log collector expects JSON.

Keep the feedback loop: test the fields

Inject the logger just as you injected *log.Logger before. An in-memory buffer gives the test direct evidence without starting a listener or changing global logging.

func TestRunAppLogsStartupIdentity(t *testing.T) {
    var out bytes.Buffer
    logger := slog.New(slog.NewTextHandler(&out, &slog.HandlerOptions{
        Level: slog.LevelInfo,
    }))

    err := runApp(func() error { return nil }, logger)
    if err != nil { t.Fatalf("runApp() error = %v", err) }

    got := out.String()
    for _, want := range []string{
        "msg=\"HTTP server starting\"",
        "version=dev",
        "revision=none",
    } {
        if !strings.Contains(got, want) {
            t.Errorf("log missing %q:\\n%s", want, got)
        }
    }
}

Keep identity selection tests separate: this test proves the logging boundary supplies named fields. It does not need to re-test linker precedence. If your defaults differ, assert your actual local fallback values.

  1. Create an injected *slog.Logger at the application boundary.
  2. Log the stable startup message with explicit version and revision attributes.
  3. Use a buffer-backed TextHandler in one focused test.
  4. Run go test ./...; the test should fail if either field disappears or becomes unnamed text.
