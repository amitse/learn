Graceful Shutdown

Drain in-flight requests on SIGTERM so your server stops cleanly — no dropped connections.

Why graceful shutdown matters

When you deploy a new binary, Kubernetes (or systemd, or Docker) sends your process SIGTERM before killing it. A server that exits immediately will drop any in-flight requests mid-response. Graceful shutdown means: stop accepting new connections, wait for all current handlers to finish, then exit.

http.Server.Shutdown was added in Go 1.8 for exactly this. pkg.go.dev → Server.Shutdown ↗

The TypeScript mental model

TypeScript (Node / Fastify)
process.on('SIGTERM', async () => {
  await server.close();
  process.exit(0);
});
Go (net/http)
quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGTERM)
<-quit  // block until signal
ctx, cancel := context.WithTimeout(
  context.Background(), 5*time.Second)
defer cancel()
srv.Shutdown(ctx)
Key concept: signal.Notify redirects OS signals into a Go channel. You block on <-quit — exactly like awaiting a promise — then call Shutdown with a deadline context so you don't wait forever.

Full working example

Here's a complete main.go with graceful shutdown wired in:

package main

import (
    "context"
    "errors"
    "log/slog"
    "net/http"
    "os"
    "os/signal"
    "syscall"
    "time"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    })

    srv := &http.Server{
        Addr:    ":8080",
        Handler: mux,
    }

    // ① Start server in a goroutine so main can keep running
    go func() {
        slog.Info("server starting", "addr", srv.Addr)
        if err := srv.ListenAndServe(); !errors.Is(err, http.ErrServerClosed) {
            slog.Error("server error", "err", err)
            os.Exit(1)
        }
    }()

    // ② Wait for SIGTERM or SIGINT (Ctrl-C in dev)
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGTERM, syscall.SIGINT)
    <-quit

    // ③ Give in-flight requests up to 5 s to finish
    slog.Info("shutting down…")
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()

    if err := srv.Shutdown(ctx); err != nil {
        slog.Error("shutdown error", "err", err)
    }
    slog.Info("server stopped")
}

Step-by-step breakdown

① Goroutine — why not call ListenAndServe directly?

ListenAndServe blocks until the server stops. If you call it directly in main, the signal-waiting code below it never runs. Spinning it off in a goroutine lets main continue to the signal channel.

ErrServerClosed is expected. When Shutdown is called, ListenAndServe returns http.ErrServerClosed — not a real error. The errors.Is check prevents logging a false alarm.

② signal.Notify — bridging OS → channel

signal.Notify(quit, syscall.SIGTERM, syscall.SIGINT) registers the channel to receive those signals. Buffer size 1 means the OS can send without blocking even if you're slightly late to read. docs ↗

<-quit blocks main goroutine — identical in feel to await someEvent.

③ context.WithTimeout — don't wait forever

Shutdown(ctx) waits for active handlers but respects the deadline. 5 seconds is a common default — long enough for most requests, short enough that Kubernetes' termination grace period (default 30 s) isn't exceeded.

Always defer cancel() immediately after WithTimeout — otherwise you leak a context goroutine even if Shutdown returns early.

Common patterns

Cleanup on shutdown (close DB connections etc.)

if err := srv.Shutdown(ctx); err != nil {
    slog.Error("shutdown", "err", err)
}
// After Shutdown returns, no handlers are running — safe to close resources
db.Close()
slog.Info("db closed")

Returning the exit code to the shell

if shutdownErr != nil {
    os.Exit(1)
}

Useful in container environments where the orchestrator checks exit codes.

What net/http.Shutdown does not handle

Shutdown closes the listener and waits for HTTP/1.1 connections to finish, but it does not interrupt long-running WebSocket or hijacked connections — you need to close those manually. docs note ↗
