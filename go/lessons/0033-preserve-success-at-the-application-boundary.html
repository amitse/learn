Preserve success at the
application boundary

Lesson 32 wrapped a failed Run with operator context. The other half of that boundary contract is simpler and just as important: when Run succeeds, pass nil through unchanged.

One branch, two honest outcomes

The application wrapper adds context only when there is an error. It must still call Run exactly once; a clean lifecycle result is not something to decorate, log as a failure, or turn into an error.

Node / TypeScript
async function runApp(run: () => Promise) {
  try {
    await run()
    // success: resolve normally
  } catch (err) {
    throw new Error("run HTTP server", { cause: err })
  }
}
Go
func wrapRun(run func() error) error {
    if err := run(); err != nil {
        return fmt.Errorf("run HTTP server: %w", err)
    }
    return nil // success: unchanged
}
Boundary rule: add the operation name only to a failure. nil already means “the HTTP lifecycle completed normally.” Keeping it transparent lets main exit normally and lets callers compose the function predictably.

Test the success contract with a tiny seam

Use the same injected func() error seam as Lesson 32. A closure can prove two things without starting a server: the dependency was called, and a successful result remains nil.

func TestWrapRunPassesSuccessThrough(t *testing.T) {
    called := false

    err := wrapRun(func() error {
        called = true
        return nil // pretend Run completed a clean shutdown
    })

    if !called {
        t.Fatal("wrapRun did not call Run")
    }
    if err != nil {
        t.Fatalf("wrapRun() error = %v; want nil", err)
    }
}

This is not a test of Go's if statement. It locks in a composition rule: the application boundary neither skips the lifecycle owner nor invents a failure after it succeeds. Go represents “no error” with the nil value of the built-in error interface.

Use the real boundary shape

Keep the production edge boring. The testable wrapper returns; main alone chooses the terminal process action for a non-nil result.

func main() {
    if err := wrapRun(func() error {
        return Run(/* listener, handler, stop context */)
    }); err != nil {
        log.Fatal(err)
    }
    // nil: main returns; process exits successfully
}

log.Fatal exits only in the failure branch. Do not call it after a clean return just to announce success: a server’s normal shutdown is routine control flow, not an operational incident.
