Classify dependency failures before retrying

A retry is a new attempt, not a way to turn every error into success. First make one small, conservative decision: was this failure interrupted by our caller, or is it a transient dependency failure worth considering for a later retry policy?

Tangible win: write a pure Go classifier that keeps cancellation and deadline exhaustion out of the retryable bucket, even after errors are wrapped.

Start with a deliberately narrow policy

Lessons 68–70 established a useful error chain: the adapter wraps failures with %w, and callers recognize their causes with errors.Is. Reuse that contract. Cancellation and an expired deadline mean the request’s time budget is over; retrying inside that same work would usually spend more of a budget that has already ended.

func retryableDependencyError(err error) bool {
    switch {
    case err == nil:
        return false
    case errors.Is(err, context.Canceled):
        return false
    case errors.Is(err, context.DeadlineExceeded):
        return false
    default:
        return true // narrow teaching policy: selected transport failures only
    }
}
Important boundary: this function classifies errors; it does not sleep, loop, or make another request. A later lesson can add bounded attempts and backoff only where the operation is safe to repeat.

The error chain still matters

TypeScript / Node

function retryable(err: unknown) {
  if (err instanceof DOMException &&
      err.name === "AbortError") return false;
  if (err instanceof TimeoutError) return false;
  return true; // policy, not magic
}

Go

func retryable(err error) bool {
  if errors.Is(err, context.Canceled) {
    return false
  }
  if errors.Is(err, context.DeadlineExceeded) {
    return false
  }
  return err != nil
}

In both languages, distinguish a stop signal from a failure the dependency may recover from. Go’s errors.Is walks an error chain, so fmt.Errorf("get profile: %w", context.DeadlineExceeded) remains recognizable.

Make the policy executable with a table

func TestRetryableDependencyError(t *testing.T) {
    transportErr := errors.New("connection reset")
    cases := []struct {
        name string
        err  error
        want bool
    }{
        {"no error", nil, false},
        {"wrapped cancellation", fmt.Errorf("get profile: %w", context.Canceled), false},
        {"wrapped deadline", fmt.Errorf("get profile: %w", context.DeadlineExceeded), false},
        {"wrapped transport failure", fmt.Errorf("get profile: %w", transportErr), true},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            if got := retryableDependencyError(tc.err); got != tc.want {
                t.Fatalf("retryableDependencyError(%v) = %v; want %v", tc.err, got, tc.want)
            }
        })
    }
}

The default is intentionally only a starting point for the adapter layer. A production policy may also reject permanent HTTP statuses or non-idempotent operations; do not smuggle those decisions into a generic “retry everything” helper.

Read the result, not the wording

Error shapeClassifyWhy
context.Canceled, wrapped or directNot retryableThe caller, client, or shutdown ended the work.
context.DeadlineExceeded, wrapped or directNot retryableThe allocated time has been exhausted.
