Wrap Run errors at the
application boundary

Lesson 31 proved that an unexpected serving failure reaches Run. Now make it actionable for an operator—add context at the composition root while preserving the original error for tests and callers.

Keep mechanism and process policy separate

Run owns HTTP lifecycle mechanics: serve, react to cancellation, and normalize only http.ErrServerClosed. The application edge owns the human-facing policy: describe what failed, then let main report it and exit. A small runApp seam lets you test that policy without testing log.Fatal, which exits the process.

Node / TypeScript
try {
  await runServer()
} catch (err) {
  throw new Error(
    "HTTP server stopped: " + err,
    { cause: err },
  )
}
Go
func runApp(/* dependencies */) error {
  if err := Run(/* ... */); err != nil {
    return fmt.Errorf(
      "run HTTP server: %w", err,
    )
  }
  return nil
}

func main() {
  if err := runApp(/* ... */); err != nil {
    log.Fatal(err)
  }
}
One job per boundary: Run does not decide whether to log or exit; main does not reinterpret normal shutdown. runApp adds only the operational context that this layer knows.

%w retains the cause

fmt.Errorf with %w creates a wrapping error. Its message gains useful context, but errors.Is can still find the original sentinel. Use %v only when you deliberately do not want an error chain.

var errAccept = errors.New("listener failed")

err := runApp(/* fake listener makes Run return errAccept */)
// err.Error(): "run HTTP server: listener failed"

if !errors.Is(err, errAccept) {
    t.Fatal("the original operational cause was lost")
}

Test the boundary—not os.Exit

Make the test inject the smallest behavior it needs: a function that returns the failure. The real application calls Run; the test passes a known error. This is the same narrow-seam thinking as the failing listener in Lesson 31.

func wrapRun(run func() error) error {
    if err := run(); err != nil {
        return fmt.Errorf("run HTTP server: %w", err)
    }
    return nil
}

func TestWrapRunPreservesCause(t *testing.T) {
    errServe := errors.New("accept failed")

    err := wrapRun(func() error { return errServe })

    if !errors.Is(err, errServe) {
        t.Fatalf("wrapRun() error = %v; want wrapped errServe", err)
    }
    if !strings.Contains(err.Error(), "run HTTP server") {
        t.Fatalf("error lacks operation context: %q", err)
    }
}

This test has two independent assertions: the message tells an operator which operation failed, and errors.Is preserves why it failed. Avoid asserting the entire message; exact wording is presentation, not the contract.
