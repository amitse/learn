Test configuration boundaries, not just errors

A config test that only checks err == nil can still accept the wrong address or timeout. Add exact assertions for a valid configuration and boundary cases that protect your HTTP server before it starts.

The missing assertion

Lesson 19 made Load deterministic by injecting a lookup function. Now use that seam to verify the typed output, not merely that loading did not fail.

TypeScript
const config = load(getEnv);
expect(config).toEqual({
  addr: ":8080",
  timeoutMs: 5000,
});
Go
got, err := Load(lookup(env))
if err != nil { t.Fatal(err) }
if got.Addr != ":8080" ||
   got.ShutdownTimeout != 5*time.Second {
    t.Errorf("got %#v", got)
}

In Go, ordinary comparisons are the assertion library. Stop with t.Fatal when Load failed: there is no useful config to inspect. Then use t.Errorf for independent field mismatches so one run can show every wrong value. See testing.T.

Add one successful row with expected values

Extend the table from Lesson 19. The expected configuration is a value, so reflect.DeepEqual is unnecessary here: every field is directly comparable.

func TestLoad(t *testing.T) {
    tests := []struct {
        name    string
        env     map[string]string
        want    Config
        wantErr bool
    }{
        {
            name: "uses safe defaults",
            env:  map[string]string{"JWT_SECRET": "dev-secret"},
            want: Config{
                Addr:            ":8080",
                JWTSecret:       "dev-secret",
                ShutdownTimeout: 5 * time.Second,
            },
        },
        {
            name: "accepts the ephemeral port",
            env:  map[string]string{"JWT_SECRET": "x", "PORT": "0"},
            want: Config{Addr: ":0", JWTSecret: "x", ShutdownTimeout: 5 * time.Second},
        },
        {
            name:    "rejects zero timeout",
            env:     map[string]string{"JWT_SECRET": "x", "SHUTDOWN_TIMEOUT": "0s"},
            wantErr: true,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := Load(lookup(tt.env))
            if (err != nil) != tt.wantErr {
                t.Fatalf("Load() error = %v, wantErr %v", err, tt.wantErr)
            }
            if tt.wantErr { return }
            if got.Addr != tt.want.Addr { t.Errorf("Addr = %q, want %q", got.Addr, tt.want.Addr) }
            if got.JWTSecret != tt.want.JWTSecret { t.Errorf("JWTSecret = %q, want %q", got.JWTSecret, tt.want.JWTSecret) }
            if got.ShutdownTimeout != tt.want.ShutdownTimeout { t.Errorf("ShutdownTimeout = %v, want %v", got.ShutdownTimeout, tt.want.ShutdownTimeout) }
        })
    }
}
One decision: port 0 is valid for an HTTP listener—it asks the OS to choose a free port. Therefore validation should allow 0..65535, while a shutdown timeout of 0s is invalid because it gives in-flight requests no time to drain.

Make the production rule match the test

If your Lesson 19 loader rejected port zero, change the lower bound. The valid port range is 0 through 65535; the net package documentation describes that :0 selects an automatically assigned port.

port, err := strconv.Atoi(getenv(lookup, "PORT", "8080"))
if err != nil || port < 0 || port > 65535 {
    return Config{}, fmt.Errorf("PORT must be 0 through 65535")
}

// A graceful shutdown deadline must leave positive time to finish work.
timeout, err := time.ParseDuration(getenv(lookup, "SHUTDOWN_TIMEOUT", "5s"))
if err != nil || timeout <= 0 {
    return Config{}, fmt.Errorf("SHUTDOWN_TIMEOUT must be positive")
}
