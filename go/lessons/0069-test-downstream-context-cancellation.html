Prove cancellation reaches a blocked downstream call

Your downstream request is created with http.NewRequestWithContext, and its errors retain their causes. Now verify the important behavior: when the incoming work is canceled, a dependency call stops waiting too.

Tangible win: write a deterministic test that starts a blocked transport, cancels its context, and proves the adapter returns a cancellation-recognizable error.

One context owns the work

Pass the handler’s context to every outbound request. When its cancellation signal arrives, the request’s context is done. A real transport can then abandon its work; a test transport can wait on req.Context().Done() to prove that the signal arrived.

Test the boundary, not timing: use a started channel so the test cancels after the transport is actually waiting. Do not use time.Sleep; it can pass or fail based on scheduler luck.

if !errors.Is(err, context.Canceled) {
    t.Fatal("cancellation was lost")

Both approaches propagate a cancellation signal. Go puts it on context.Context, which travels explicitly into http.NewRequestWithContext.

Make a transport that blocks until canceled

type roundTripFunc func(*http.Request) (*http.Response, error)
func (f roundTripFunc) RoundTrip(r *http.Request) (*http.Response, error) { return f(r) }

func TestGetProfileCancelsBlockedRequest(t *testing.T) {
    started := make(chan struct{})
    client := &http.Client{Transport: roundTripFunc(func(r *http.Request) (*http.Response, error) {
        close(started)                 // the request reached the dependency boundary
        <-r.Context().Done()           // wait for its caller to cancel
        return nil, r.Context().Err()  // context.Canceled
    })}

    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()
    result := make(chan error, 1)
    go func() { _, err := getProfile(ctx, client, "https://profiles.example"); result <- err }()

    <-started // synchronization, not a sleep
    cancel()
    if err := <-result; !errors.Is(err, context.Canceled) {
        t.Fatalf("error = %v; want a wrapped context.Canceled", err)
    }
}

The buffered result channel lets the goroutine finish even if the assertion fails. Returning r.Context().Err() models a cancellation-aware transport; the wrapper from lesson 68 must preserve it.

What this does—and does not—prove

It proves: the exact context passed to getProfile reaches the outbound request, a blocked dependency observes cancellation, and the returned error remains inspectable with errors.Is.

It does not prove: a particular external API has received a cancellation packet, or that a retry policy is correct. Those are separate contracts.
