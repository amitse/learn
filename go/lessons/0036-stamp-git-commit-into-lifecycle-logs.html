Stamp a Git commit into
lifecycle logs

A release version answers “what release?” A commit SHA answers the sharper question: exactly which source revision produced this binary? Add it beside Lesson 35’s version at the application boundary.

The one idea: record both identities

Keep one linker-set string for a human release label and one for the immutable source revision. Give each a truthful local fallback, then log both once when the process starts, stops, or fails.

Node / TypeScript
// CI commonly injects both values.
logger.info({
  version: process.env.BUILD_VERSION,
  revision: process.env.GIT_SHA,
}, "HTTP server starting")
Go
// Both must be vars for -X.
var version = "dev"
var revision = "none"

logger.Printf(
  "HTTP server starting version=%s revision=%s",
  version, revision,
)
Why two fields? v1.4.0 is readable and may be rebuilt. A full commit SHA identifies the exact source revision. They describe the binary, so they remain process metadata—not request context or response data.

Build one identifiable binary

In CI, resolve the commit once and hand its value to the linker. The Go linker’s -X option sets a string variable named as importpath.name. For values declared in package main, that is main.version and main.revision.

# Resolve these in the CI checkout, not at request time.
VERSION=v1.4.0
REVISION=$(git rev-parse HEAD)

go build \
  -ldflags "-X main.version=$VERSION -X main.revision=$REVISION" \
  -o api \
  ./cmd/server

git rev-parse HEAD prints the object name of the commit named by HEAD; using the full value avoids short-SHA ambiguity. The Git documentation for rev-parse describes this revision-resolution command.

Make the boundary log the pair

var version = "dev"
var revision = "none"

func main() {
    logger := log.Default()
    logger.Printf("HTTP server starting version=%s revision=%s", version, revision)

    if err := runApp(runServer, logger); err != nil {
        logger.Printf("HTTP server failed version=%s revision=%s err=%v", version, revision, err)
        os.Exit(1)
    }
}

func runApp(run func() error, logger *log.Logger) error {
    if err := run(); err != nil {
        return fmt.Errorf("run HTTP server: %w", err)
    }
    logger.Printf("HTTP server stopped version=%s revision=%s", version, revision)
    return nil
}

This extends—not replaces—the prior lifecycle contract: runApp still returns an error, and main still owns the exit decision. The additional fields only identify the artifact that emitted the event.

Test the source defaults; smoke-test the build hand-off

  1. Unit test the local defaults. Use the existing buffer-backed logger and require both version=dev and revision=none in a clean-stop log.
  2. Build a stamped artifact in CI. Pass values only through -ldflags; do not mutate package globals in a test.
  3. Run the artifact once. Require its startup line to contain the expected version and SHA. That validates the real CI → linker → binary hand-off.
func TestRunAppLogsLocalBuildIdentity(t *testing.T) {
    var output bytes.Buffer
    logger := log.New(&output, "", 0)

    if err := runApp(func() error { return nil }, logger); err != nil {
        t.Fatalf("runApp() error = %v", err)
    }
    got := output.String()
    if !strings.Contains(got, "version=dev") ||
        !strings.Contains(got, "revision=none") {
        t.Fatalf("log = %q; want local build identity", got)
    }
}
