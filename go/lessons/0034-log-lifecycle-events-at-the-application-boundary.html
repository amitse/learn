Log lifecycle events at the
application boundary

Your Run function already owns serving and shutdown; Lesson 33 made its nil success result transparent. Add one useful operator signal without leaking logging policy into routes or handlers: log the lifecycle outcome at the process edge.

Log where the meaning is known

A handler knows request details. Run knows HTTP mechanics. The composition root knows this is the application’s lifecycle, so it is the right place to say whether the process stopped cleanly or failed. Keep the returning function testable; let main choose the terminal action.

Node / TypeScript
try {
  await runServer()
  logger.info("server stopped")
} catch (err) {
  logger.error({ err }, "server failed")
  process.exitCode = 1
}
Go
func runApp(run func() error, log *log.Logger) error {
  if err := run(); err != nil {
    return fmt.Errorf("run HTTP server: %w", err)
  }
  log.Print("HTTP server stopped")
  return nil
}
One boundary rule: the success log comes after run() returns nil. It reports a completed lifecycle; it must not claim that the server stopped before active requests have drained.

Keep failure policy in main

runApp emits a normal completion event and returns errors to its caller. It does not call log.Fatal: that method exits the process, which makes the behavior hard to test and prevents a caller from choosing another policy.

func main() {
    logger := log.Default()

    if err := runApp(func() error {
        return Run(/* listener, handler, stop context */)
    }, logger); err != nil {
        logger.Print(err)
        os.Exit(1)
    }
}

Logger.Print writes a log record; os.Exit(1) is explicitly the process-edge choice after a returned failure. A normal nil return falls off the end of main with status 0.

Test the observable event, not standard output

Inject a *log.Logger configured with a bytes.Buffer. This gives the test a deterministic observation point—no global logger mutation, server, port, or sleep.

func TestRunAppLogsCleanStop(t *testing.T) {
    var output bytes.Buffer
    logger := log.New(&output, "", 0)

    err := runApp(func() error { return nil }, logger)

    if err != nil {
        t.Fatalf("runApp() error = %v; want nil", err)
    }
    if got := output.String(); !strings.Contains(got, "HTTP server stopped") {
        t.Fatalf("log = %q; want clean-stop event", got)
    }
}

Use log.New rather than changing the package-level default logger. The standard library constructor accepts any io.Writer, and a buffer is an in-memory writer. Set flags to 0 so timestamps do not make an exact or substring assertion noisy.
