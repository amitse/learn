Wire a server to an ephemeral listener

Your configuration now permits :0. Use net.Listen to bind that address, inspect the actual port the OS chose, and serve your existing mux without a fragile hard-coded test port.

Why ListenAndServe is too opaque here

http.ListenAndServe(addr, handler) both creates a listener and serves it. That is perfect in main, but a wiring test needs the listener value so it can discover the assigned address and close it deterministically. Split the two operations: net.Listen, then srv.Serve.

TypeScript
const server = app.listen(0);
await once(server, "listening");
const { port } = server.address();
// fetch(`http://127.0.0.1:${port}/health`)
await close(server);
Go
ln, err := net.Listen("tcp", ":0")
if err != nil { return err }
addr := ln.Addr().String()

go srv.Serve(ln)
defer srv.Close()

Port 0 asks the OS for an available ephemeral port. After Listen succeeds, ln.Addr() is the concrete address—not :0. The Go net.Listen documentation specifies this behavior.

The smallest testable server factory

Keep server construction in a function. It takes your already-validated Config and handler, while main remains the composition root.

func NewServer(cfg config.Config, h http.Handler) *http.Server {
    return &http.Server{
        Addr:    cfg.Addr,
        Handler: h,
    }
}

This factory has no network side effect. Its unit test can assert srv.Addr and srv.Handler directly. The next layer—the listener test—proves that its configured address can actually bind.

Bind once, discover the port, make one request

Use an explicit loopback host in the client URL. A listener address such as [::]:43211 may mean “all interfaces,” whereas 127.0.0.1 reliably reaches the local server.

func TestHealthOverEphemeralListener(t *testing.T) {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(http.StatusNoContent)
    })

    srv := NewServer(config.Config{Addr: "127.0.0.1:0"}, mux)
    ln, err := net.Listen("tcp", srv.Addr)
    if err != nil { t.Fatal(err) }
    t.Cleanup(func() { _ = srv.Close() })

    go func() {
        err := srv.Serve(ln)
        if err != nil && !errors.Is(err, http.ErrServerClosed) {
            t.Errorf("Serve: %v", err)
        }
    }()

    url := "http://" + ln.Addr().String() + "/health"
    resp, err := http.Get(url)
    if err != nil { t.Fatal(err) }
    defer resp.Body.Close()
    if resp.StatusCode != http.StatusNoContent {
        t.Errorf("status = %d, want %d", resp.StatusCode, http.StatusNoContent)
    }
}
Important distinction: srv.Addr remains the requested address (127.0.0.1:0); ln.Addr() is the address that was actually bound. Build the test URL from the latter.

Three moves to reuse

1Create the listener first with net.Listen("tcp", cfg.Addr).

2Start srv.Serve(ln) in a goroutine, because it blocks while serving.

3Make the request against ln.Addr().String(); close the server with t.Cleanup.

The http.Server.Serve docs state that it returns http.ErrServerClosed after Close or Shutdown; filter that expected result just as you did in the graceful-shutdown lesson.

Quick check

Choose an answer for instant feedback.

1. After binding 127.0.0.1:0, which value belongs in the client URL?

2. Why run srv.Serve(ln) in a goroutine?

3. Which Serve error is expected after the cleanup closes the server?

Ask your teacher: ask how to replace srv.Close() in this test with graceful srv.Shutdown(ctx) and still make cleanup reliable.
