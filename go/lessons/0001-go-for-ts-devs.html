Go for TypeScript Devs

The 20% of Go syntax that covers 80% of what you'll write — mapped directly to TypeScript.

Win for this lesson: You can read and write basic Go — variables, functions, types, and structs — without your TypeScript brain fighting you.

The Mental Shift

TypeScript compiles to JavaScript and runs in a runtime. Go compiles to a native binary and runs directly on the OS. There's no node_modules, no package.json, no runtime dependency. You go build and get an executable.

The other big shift: Go is statically typed with no implicit conversions — stricter than TS in some ways, simpler in others. And there's no null. Zero values everywhere.

Variables

TypeScript
const name: string = "Amit"
let age: number = 30
let active: boolean = true

// type inferred
const score = 100
Go
var name string = "Amit"
var age int = 30
var active bool = true

// shorthand (inferred) — use this always
score := 100
:= is your new const. Inside functions, always use := for new variables. var is mostly for package-level declarations.

Functions

TypeScript
function add(a: number, b: number): number {
  return a + b
}

// multiple return values? Use an object
function divide(a: number, b: number)
  : { result: number; err: string | null } {
  if (b === 0) return { result: 0, err: "div by zero" }
  return { result: a / b, err: null }
}
Go
func add(a int, b int) int {
  return a + b
}

// Go has native multiple return values
func divide(a, b float64) (float64, error) {
  if b == 0 {
    return 0, fmt.Errorf("div by zero")
  }
  return a / b, nil
}
Multiple return values are native in Go — no wrapper object needed. This is how Go handles errors: always return (value, error) and check the error immediately.

Error Handling — The Big One

In TypeScript you throw and try/catch. Go doesn't do that. Functions return an error as a second value, and you check it every time.

TypeScript
try {
  const data = await fetchUser(id)
  console.log(data)
} catch (err) {
  console.error(err)
}
Go
data, err := fetchUser(id)
if err != nil {
  fmt.Println(err)
  return
}
fmt.Println(data)
You will forget to check errors at first. The Go compiler won't catch it. Make it a habit: every := that could return an error gets an if err != nil block right after.

Structs (Go's version of interfaces/types)

TypeScript
interface User {
  name: string
  age:  number
}

const u: User = { name: "Amit", age: 30 }
console.log(u.name)
Go
type User struct {
  Name string
  Age  int
}

u := User{Name: "Amit", Age: 30}
fmt.Println(u.Name)
Capital letters = exported (public). Lowercase = unexported (private). This applies to struct fields, functions, variables — everything. No export keyword, just capitalisation.

Your First Go Program

Every Go program starts with a main package and a main() function. It's the entry point — same idea as index.ts.

Go — main.go
package main

import "fmt"

type User struct {
  Name string
  Age  int
}

func greet(u User) string {
  return fmt.Sprintf("Hello, %s! You are %d years old.", u.Name, u.Age)
}

func main() {
  u := User{Name: "Amit", Age: 30}
  msg := greet(u)
  fmt.Println(msg)
}
