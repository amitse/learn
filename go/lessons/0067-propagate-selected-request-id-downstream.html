Propagate the selected request ID downstream

Your middleware has chosen one safe request ID and uses it consistently in its own response and logs. When this service calls another HTTP service, carry that same selected value across the outbound boundary—never the raw inbound header.

Tangible win: write and test one small outbound-request helper that puts the context-selected request ID into a downstream X-Request-ID header.

Selection happens once

Lesson 66 established the selection contract: trusted and valid input may win; everything else gets a generated fallback. At an outbound boundary, do not reopen that decision by copying r.Header.Get("X-Request-ID"). Read the selected value from the request context instead.

Why: blindly forwarding the inbound header would split correlation. The client could see and operators could log generated-7, while the downstream service receives client-9. The outbound call is a new boundary, but its correlation value is already decided.

Make a fresh outbound request, then set one header

TypeScript / Node

async function fetchProfile(req: Request) {
  const id = req.context.requestId; // selected
  return fetch(profileURL, {
    headers: { "X-Request-ID": id },
  });
}

Go

func newDownstreamRequest(
    ctx context.Context, url string,
) (*http.Request, error) {
    req, err := http.NewRequestWithContext(
        ctx, http.MethodGet, url, nil)
    if err != nil { return nil, err }
    req.Header.Set("X-Request-ID", RequestID(ctx))
    return req, nil
}

http.NewRequestWithContext gives the outbound call the existing cancellation/deadline context. Header.Set deliberately establishes one value for this header; it does not copy the inbound request’s whole header map, which could accidentally forward credentials or hop-by-hop headers.

Test the wire value with an in-process server

func TestDownstreamRequestUsesSelectedID(t *testing.T) {
    gotID := ""
    downstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        gotID = r.Header.Get("X-Request-ID")
        w.WriteHeader(http.StatusNoContent)
    }))
    defer downstream.Close()

    ctx := context.WithValue(context.Background(), requestIDKey{}, "generated-7")
    req, err := newDownstreamRequest(ctx, downstream.URL)
    if err != nil { t.Fatal(err) }

    res, err := downstream.Client().Do(req)
    if err != nil { t.Fatal(err) }
    res.Body.Close()
    if gotID != "generated-7" {
        t.Fatalf("downstream X-Request-ID = %q; want generated-7", gotID)
    }
}

This test observes the header received by the downstream handler, rather than inspecting only the request object before the client sends it. It proves the boundary contract while avoiding a real network dependency.

Keep the responsibility narrow

  • Middleware selects and stores the request ID once.
  • Outbound adapter reads that selected ID and writes it to the new downstream request.
  • Do not copy raw inbound headers, regenerate a different ID, or introduce W3C trace-context semantics here. Those are separate policies and adapters.

Quick check

An untrusted client sends X-Request-ID: client-9. Middleware selected generated-7. Which value belongs on an outbound request to the profile service?
