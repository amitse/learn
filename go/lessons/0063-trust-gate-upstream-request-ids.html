Trust-gate upstream request IDs

Your middleware can now generate and log a request ID safely. Before it ever reuses an ID from X-Request-ID, make one fact explicit: did this request arrive through infrastructure you trust to set that header?

Tangible win: write and test a tiny policy that ignores a client-supplied ID unless a trusted proxy boundary has already vouched for the request.

The header is data, not proof

Any direct client can send X-Request-ID: invoice-42. The header’s presence therefore cannot establish where it came from. Trust must be established outside this middleware—for example, by routing that only a private proxy can reach, then attaching a server-owned trustedProxy fact to the request. This lesson is only about the gate; format validation comes next.

TypeScript / Node

function chooseID(input: {
  trustedProxy: boolean
  upstreamID: string
  generatedID: string
}) {
  return input.trustedProxy && input.upstreamID !== ""
    ? input.upstreamID
    : input.generatedID
}

Go

func chooseRequestID(trustedProxy bool,
    upstreamID, generatedID string) string {
    if trustedProxy && upstreamID != "" {
        return upstreamID
    }
    return generatedID
}
Boundary rule: r.Header.Get("X-Request-ID") tells you only the supplied value. It does not tell you whether a trusted proxy supplied it. Keep network authentication / proxy routing at the edge, and pass a server-owned trust decision inward.

Make the policy testable

Keep selection pure. The selector has no *http.Request, no environment lookup, and no network-address parsing. That makes its security rule easy to see and table-test.
func TestChooseRequestID(t *testing.T) {
    tests := []struct {
        name                    string
        trustedProxy            bool
        upstreamID, generatedID string
        want                    string
    }{
        {"trusted proxy may preserve ID", true, "edge-91", "new-7", "edge-91"},
        {"direct client cannot choose ID", false, "attacker-picked", "new-7", "new-7"},
        {"trusted proxy with no ID gets generated one", true, "", "new-7", "new-7"},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := chooseRequestID(tt.trustedProxy, tt.upstreamID, tt.generatedID)
            if got != tt.want { t.Errorf("got %q; want %q", got, tt.want) }
        })
    }
}
Wire the trusted fact, not a client claim. An outer proxy/authentication layer can place a private typed marker in context. Request-ID middleware reads that marker and the header, then calls the selector. Do not use a public header such as X-Forwarded-For as the trust signal: it is also input unless your edge has defined how it is sanitized.
type trustedProxyKey struct{}

func withTrustedProxy(r *http.Request) *http.Request {
    ctx := context.WithValue(r.Context(), trustedProxyKey{}, true)
    return r.WithContext(ctx)
}

func isFromTrustedProxy(ctx context.Context) bool {
    trusted, _ := ctx.Value(trustedProxyKey{}).(bool)
    return trusted
}

// At the request-ID boundary:
id := chooseRequestID(isFromTrustedProxy(r.Context()),
    r.Header.Get("X-Request-ID"), generatedID)
Important scope: this context marker is a transport-internal capability, not authentication by itself. Only edge code that has already enforced the proxy boundary may call withTrustedProxy.
