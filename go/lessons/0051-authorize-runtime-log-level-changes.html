Authorize runtime log-level changes

Lesson 50 made log-level changes serial and auditable. The next rule is simpler: an identity must not be able to change production logging merely because it reached a future admin route. Put the permission check in the one control that owns the change.

Tangible win

You will make LogLevelControl.Set reject a caller lacking logs:write, before it reads the level, mutates it, or writes an audit event. A tiny test proves an unauthorized call has no side effect.

Authorization is a business boundary, not a route detail

An HTTP middleware may eventually authenticate a request and create a trusted Principal. But a route check alone is fragile: another transport—CLI, job, RPC, or a future route—could call the control incorrectly. The control owns the sensitive action, so it enforces the permission too.

type Principal = {
  id: string;
  permissions: Set<string>;

Go

type Principal struct {
    ID          string
    Permissions map[string]bool
}

func (p Principal) Can(permission string) bool {
    return p.Permissions[permission]
}

Principal is deliberately application data, not context.Context. An authentication adapter may obtain it from an HTTP request; the control receives it explicitly, which makes its authority requirement visible in every call and easy to test.

Reject before every side effect

var ErrForbidden = errors.New("log-level change forbidden")

func (c *LogLevelControl) Set(
    ctx context.Context, actor Principal, to slog.Level,
) error {
    if !actor.Can("logs:write") {
        return ErrForbidden
    }

    c.mu.Lock()
    defer c.mu.Unlock()

    from := c.level.Level()
    c.level.Set(to)
    c.audit.InfoContext(ctx, "log level changed",
        "actor", actor.ID, "from", from, "to", to)
    return nil
}
Ordering matters: authorization is outside the mutex because it does not inspect or change the protected level state. It happens before the read → set → audit transition. Authorized calls still serialize exactly as in Lesson 50.

What this does—and does not—trust

  • It trusts the adapter that constructs a Principal; that is where JWT/session verification belongs.
  • It does not trust a raw HTTP header such as X-Role: admin, a request body field, or an arbitrary actor string as proof of permission.
  • It records actor.ID only after authorization succeeds. The audit event is evidence of an accepted operation, not a log of rejected guesses.
Do not add an unprotected “temporary” admin endpoint. Until authentication is wired, keep this control unexposed to HTTP. A correct authorization seam is useful now because the future adapter has one safe place to delegate to.

Test denial as “no mutation, no audit”

func TestSetRejectsPrincipalWithoutLogsWrite(t *testing.T) {
    var level slog.LevelVar
    level.Set(slog.LevelInfo)
    var out bytes.Buffer
    audit := slog.New(slog.NewJSONHandler(&out, nil))
    control := NewLogLevelControl(&level, audit)

    err := control.Set(context.Background(), Principal{
        ID: "viewer-42", Permissions: map[string]bool{},
    }, slog.LevelDebug)

    if !errors.Is(err, ErrForbidden) {
        t.Fatalf("Set error = %v, want ErrForbidden", err)
    }
    if got, want := level.Level(), slog.LevelInfo; got != want {
        t.Fatalf("level = %v, want %v", got, want)
    }
    if got := out.String(); got != "" {
        t.Fatalf("audit output = %q, want no event", got)
    }
}

This test checks the operational contract rather than private implementation: an unauthorized principal leaves the level and audit stream unchanged. Add a second focused test with Permissions: map[string]bool{"logs:write": true} to retain the accepted-change behavior from Lessons 49–50.
