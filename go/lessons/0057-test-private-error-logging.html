Test private error logging
without leaking it to clients

Your JSON error contract is now tested. Close the observability loop: an unexpected failure must be generic in the HTTP response and specific in the server log.

Win: write one focused test that proves the same internal cause is visible to operators but absent from the public response.

The boundary has two audiences

Client

Safe contract

500 + {"error":"internal server error"}. No database host, token, or wrapped implementation text.

Operator

Useful evidence

A structured event with a stable message and the actual error as a named attribute.

This is not contradictory. The handler classifies the error for the client, then logs the private cause for the operator.

The smallest route change

if err := control.Set(r.Context(), principal, level); err != nil {
    if errors.Is(err, ErrForbidden) {
        writeJSONError(w, http.StatusForbidden, "forbidden")
        return
    }

    logger.Error("log-level change failed", "error", err)
    writeJSONError(w, http.StatusInternalServerError, "internal server error")
    return
}

slog.Logger.Error records an error-level event; named attributes make the cause queryable. Do not put err.Error() into the public JSON message.

TS ↔ Go: same separation, different tools

TypeScript / Node

logger.error({ err }, "change failed");
res.status(500).json({
  error: "internal server error"
});

Go

logger.Error("change failed",
  "error", err)
writeJSONError(w, 500,
  "internal server error")

Test both sides of the boundary

Use a distinctive fake private value. It makes a weak test precise: if that exact value appears in the response, the route leaked it; if it is absent from the log, observability was lost.

func TestSetLevel_internalErrorIsLoggedButNotExposed(t *testing.T) {
    var logs bytes.Buffer
    logger := slog.New(slog.NewJSONHandler(&logs, nil))
    private := errors.New("postgres://admin:secret@db.internal:5432")
    control := &controlSpy{err: private}
    h := newSetLevelHandler(control, logger)

    r := httptest.NewRequest(http.MethodPut, "/ops/log-level", nil)
    r = r.WithContext(withOperator(r.Context()))
    w := httptest.NewRecorder()
    h.ServeHTTP(w, r)

    if w.Code != http.StatusInternalServerError { t.Fatalf("got %d", w.Code) }
    if strings.Contains(w.Body.String(), private.Error()) { t.Fatal("private cause leaked") }
    if !strings.Contains(logs.String(), private.Error()) { t.Fatal("private cause not logged") }
}
Why raw-string checks are right here: you already decode the client JSON to test its public contract (Lesson 56). This test asks a different question—whether one exact diagnostic value crossed each boundary. A captured bytes.Buffer answers it without a real server or external log sink.

Do it in this order

1
Create a bytes.Buffer and inject a JSON slog logger into the handler.
2
Make the existing control spy return a distinctive unexpected error—not ErrForbidden.
3
Require 500, then prove the private string is absent from w.Body.
4
Require that same string in the captured structured log. Keep the stable event message separate from the changing cause.

What is the key assertion for the client side of this test?

Carry forward: a safe public error and a useful private log are a paired contract. When you add an unexpected-error path, test both—generic response out, diagnostic event retained.
