Validate trusted upstream request IDs

Lesson 63 decided who may supply an upstream ID. Now decide which values may enter your response headers, request context, and logs. Trust and validity are separate checks.

Tangible win: add one bounded allowlist validator so a trusted proxy’s malformed X-Request-ID falls back to a server-generated ID.

Trust first, then validate

A trusted ingress can still send a buggy or unexpectedly large value. Define the small contract your application accepts: 1–128 ASCII characters, each a letter, digit, -, _, or .. This is an application policy—not a claim that other header values are universally invalid.

TypeScript / Node

const validID = (id: string) =>
  /^[A-Za-z0-9._-]{1,128}$/.test(id)

function selectID(trusted: boolean,
  upstream: string, generated: string) {
  return trusted && validID(upstream)
    ? upstream : generated
}

Go

func validUpstreamID(id string) bool {
    if len(id) == 0 || len(id) > 128 {
        return false
    }
    for _, c := range id {
        if !(c >= 'a' && c <= 'z' ||
            c >= 'A' && c <= 'Z' ||
            c >= '0' && c <= '9' ||
            c == '-' || c == '_' || c == '.') {
            return false
        }
    }
    return true
}
Why an allowlist? It gives a predictable, bounded identifier contract. In particular, reject whitespace, control characters, and arbitrary Unicode rather than “cleaning” them into a different identifier. When validation fails, use the already-generated server ID—not an error message and not a partially repaired upstream value.

Compose the two gates

Generate first. Preserve the earlier failure behavior: if generation fails, return the safe 500 and do not continue.
generatedID, err := generateID()
if err != nil {
    logger.Error("request ID generation failed", "error", err)
    writeJSONError(w, http.StatusInternalServerError, "internal server error")
    return
}

upstreamID := r.Header.Get("X-Request-ID")
id := generatedID
if isFromTrustedProxy(r.Context()) && validUpstreamID(upstreamID) {
    id = upstreamID
}

w.Header().Set("X-Request-ID", id)
next.ServeHTTP(w, r.WithContext(withRequestID(r.Context(), id)))
Do not trim or normalize here. If " edge-91 " becomes "edge-91", logs and a response silently describe a value the proxy never supplied. Reject it and retain the generated ID. If your organization needs another identifier grammar, document and test that exact grammar instead.

Table-test the policy

func TestChooseRequestID(t *testing.T) {
    tests := []struct {
        name                    string
        trusted                 bool
        upstream, generated, want string
    }{
        {"trusted allowed value", true, "edge-91.ab", "new-7", "edge-91.ab"},
        {"trusted value with space falls back", true, "edge 91", "new-7", "new-7"},
        {"trusted oversized value falls back", true, strings.Repeat("a", 129), "new-7", "new-7"},
        {"untrusted allowed-looking value falls back", false, "attacker-91", "new-7", "new-7"},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := chooseRequestID(tt.trusted, tt.upstream, tt.generated)
            if got != tt.want { t.Errorf("got %q; want %q", got, tt.want) }
        })
    }
}

Have chooseRequestID call validUpstreamID. The test rows state the full policy: provenance must be trusted and the value must obey the bounded grammar.
