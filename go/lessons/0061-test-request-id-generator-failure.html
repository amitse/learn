Test a request-ID generator failure

Lesson 60 made request IDs deterministic on the normal path. Now close the other branch: if the injected generator fails, your middleware must send the existing safe JSON 500 and must not call the downstream handler.

Tangible win: one focused test proves that an internal entropy failure neither leaks its private cause nor runs application code without a request ID.

The one idea

A request ID is created before middleware can set X-Request-ID or derive request context. When creation fails, stop at that boundary. Render the same public error contract used for unexpected failures; retain the detailed error only for server-side diagnostics if you have a logger there.

TypeScript / Node

try {
  const id = makeID()
  res.setHeader("X-Request-ID", id)
  next()
} catch (err) {
  res.status(500).json({
    error: "internal server error"
  })
  // no next()
}

Go / net/http

id, err := makeID()
if err != nil {
  writeJSONError(w,
    http.StatusInternalServerError,
    "internal server error")
  return // no next.ServeHTTP
}

Build the test from the observable contract

Return a distinctive private error. The generator is already a seam, so no real randomness needs to fail. Use an unmistakable value and later prove it is absent from the HTTP body.
const privateCause = "entropy device unavailable"
makeID := func() (string, error) {
    return "", errors.New(privateCause)
}

Go errors are values; the conventional branch is to check a returned non-nil error immediately. See Error handling and Go.

Make delegation observable. A boolean is enough here. The handler deliberately does no useful HTTP work—its only job is to prove it was not reached.
called := false
next := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    called = true
})
Assert all three public-boundary facts. Require 500, decode the owned JSON envelope, and require no delegation. Also reject the private cause in the body; that keeps the public/private split from Lesson 57 intact.
func TestRequestIDGeneratorFailureIsSafe(t *testing.T) {
    const privateCause = "entropy device unavailable"
    makeID := func() (string, error) {
        return "", errors.New(privateCause)
    }
    called := false
    next := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        called = true
    })

    w := httptest.NewRecorder()
    RequestID(next, makeID).ServeHTTP(w,
        httptest.NewRequest(http.MethodGet, "/", nil))

    if w.Code != http.StatusInternalServerError {
        t.Fatalf("status = %d, want 500", w.Code)
    }
    var got errorResponse
    if err := json.NewDecoder(w.Body).Decode(&got); err != nil {
        t.Fatal(err)
    }
    if got.Error != "internal server error" {
        t.Errorf("public error = %q", got.Error)
    }
    if strings.Contains(w.Body.String(), privateCause) {
        t.Error("private generator error leaked to client")
    }
    if called { t.Error("next handler was called") }
}

Why no downstream call?

Without an ID, a downstream error event may lose the correlation contract you just established. More importantly, execution after a failed prerequisite is accidental behavior. The early return makes the policy explicit: either one ID exists for the request, or the request ends safely at the boundary.

Optional next refinement: if your request-ID middleware has an injected *slog.Logger, log a stable event with the generator error as a private "error" attribute. Keep that separate from this HTTP contract test: the response must never serialize err.Error().
