Validated environment configuration

Turn process environment strings into one typed, checked Config value at startup—so a missing JWT secret or malformed port fails before your HTTP server accepts traffic.

The boundary: environment → typed config

In Node, libraries such as zod often validate process.env on boot. Go’s standard library gives you the same building blocks directly: os.LookupEnv tells you whether a variable exists, and parsing functions turn strings into useful types. Do this once in main; don’t scatter os.Getenv calls through handlers.

TypeScript
const port = Number(process.env.PORT ?? 8080)
if (!process.env.JWT_SECRET) {
  throw new Error("JWT_SECRET is required")
}
Go
port, err := strconv.Atoi(getenv("PORT", "8080"))
if err != nil { return Config{}, err }

secret, ok := os.LookupEnv("JWT_SECRET")
if !ok || secret == "" { /* fail */ }
Important: os.Getenv("JWT_SECRET") returns "" both when the variable is unset and when it is explicitly empty. Use LookupEnv when that distinction—or clear validation—matters.

Build one loader

Put this in internal/config/config.go. It has one job: accept an environment lookup function, apply safe defaults, and reject invalid startup state.

package config

import (
    "fmt"
    "os"
    "strconv"
    "strings"
    "time"
)

type Config struct {
    Addr            string
    JWTSecret       string
    ShutdownTimeout time.Duration
}

func Load() (Config, error) {
    port := getenv("PORT", "8080")
    portNum, err := strconv.Atoi(port)
    if err != nil || portNum < 1 || portNum > 65535 {
        return Config{}, fmt.Errorf("PORT must be a number from 1 to 65535")
    }

    secret, ok := os.LookupEnv("JWT_SECRET")
    if !ok || strings.TrimSpace(secret) == "" {
        return Config{}, fmt.Errorf("JWT_SECRET is required")
    }

    timeout, err := time.ParseDuration(getenv("SHUTDOWN_TIMEOUT", "5s"))
    if err != nil || timeout <= 0 {
        return Config{}, fmt.Errorf("SHUTDOWN_TIMEOUT must be a positive duration")
    }

    return Config{
        Addr:            ":" + port,
        JWTSecret:       secret,
        ShutdownTimeout: timeout,
    }, nil
}

func getenv(key, fallback string) string {
    if value, ok := os.LookupEnv(key); ok && value != "" {
        return value
    }
    return fallback
}

1Defaults make local development easy: no PORT means :8080; no timeout means 5s.

2Required values must not silently default. A generated fallback JWT secret would make tokens invalid after each restart; fail fast instead.

3Parse at the edge. The rest of the app receives a time.Duration, not a string it must parse again.

Wire it into the server

func main() {
    cfg, err := config.Load()
    if err != nil {
        log.Fatal("configuration error: ", err)
    }

    // cfg.JWTSecret goes to auth.AuthMiddleware.
    srv := &http.Server{Addr: cfg.Addr, Handler: mux}

    // During SIGTERM handling:
    ctx, cancel := context.WithTimeout(context.Background(), cfg.ShutdownTimeout)
    defer cancel()
    _ = srv.Shutdown(ctx)
}

Run locally with explicit values:

JWT_SECRET=dev-only-secret PORT=8081 SHUTDOWN_TIMEOUT=8s go run ./cmd/server

Do not commit secrets to Git. Your deployment platform should supply JWT_SECRET; a local .env file is a convenience, not a substitute for a real secret-management policy.

Quick check

Choose an answer for instant feedback.

1. Which API can distinguish an unset variable from a variable set to an empty string?

2. Why parse SHUTDOWN_TIMEOUT in config.Load rather than in shutdown code?

3. What should your server do if JWT_SECRET is missing?

Ask your teacher: if you want, ask for a table-driven test for config.Load next. Configuration loading is deliberately easy to test once the environment lookup is injected.
