Table-test the request-ID propagation matrix

You proved one invalid trusted-header case in Lesson 65. Now make the policy durable: one table should cover every meaningful provenance-and-format combination and require the selected ID in both observable outputs.

Tangible win: turn four request-ID rules into a compact middleware test that catches an accidental header or log propagation regression.

One decision matrix, two outputs

Selection has two inputs: did server-controlled infrastructure mark the request as trusted, and is the supplied ID valid? The response header and the private log event must agree with that single decision.

Do not add rows for every invalid spelling. That grammar belongs in the validator’s unit test. This is a propagation test: representative selection branches, then the two outputs your middleware owns.

Run the real middleware for each row

func TestRequestIDPropagation(t *testing.T) {
    tests := []struct {
        name, upstream, want string
        trusted              bool
    }{
        {"trusted valid", "edge-91", "edge-91", true},
        {"trusted invalid", "bad id", "generated-7", true},
        {"untrusted valid", "client-9", "generated-7", false},
        {"missing upstream", "", "generated-7", false},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            var logs bytes.Buffer
            logger := slog.New(slog.NewJSONHandler(&logs, nil))
            next := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
                logger.Error("request failed", "request_id", RequestID(r.Context()))
                writeJSONError(w, http.StatusInternalServerError, "internal server error")
            })
            generate := func() (string, error) { return "generated-7", nil }
            h := RequestIDMiddleware(generate, logger)(next)

            req := httptest.NewRequest(http.MethodGet, "/boom", nil)
            if tt.upstream != "" { req.Header.Set("X-Request-ID", tt.upstream) }
            if tt.trusted { req = req.WithContext(withTrustedProxy(req.Context())) }
            rr := httptest.NewRecorder()
            h.ServeHTTP(rr, req)

            if got := rr.Header().Get("X-Request-ID"); got != tt.want {
                t.Fatalf("header = %q; want %q", got, tt.want)
            }
            var event struct { RequestID string `json:"request_id"` }
            if err := json.Unmarshal(bytes.TrimSpace(logs.Bytes()), &event); err != nil { t.Fatal(err) }
            if event.RequestID != tt.want { t.Fatalf("log ID = %q; want %q", event.RequestID, tt.want) }
        })
    }
}
Boundary discipline: generate a new logger and buffer inside every subtest. Otherwise an earlier JSON event can contaminate the next row, and a decoding failure tells you nothing about request-ID policy.

What this test deliberately does not prove

It does not retest every character rule, the secure generator’s randomness, or the logging formatter’s timestamp. Those are separate contracts. Here, deterministic generation makes the expected outcome exact, and t.Run names the policy branch that failed.

Quick check

An untrusted client supplies the valid-looking value client-9. The generator returns generated-7. What should the table row require?
