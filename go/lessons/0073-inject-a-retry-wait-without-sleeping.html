Inject a retry wait without sleeping

Yesterday’s retry makes one extra call for an approved idempotent read. Before adding a real delay, make the wait a dependency so the policy stays observable and tests stay instant.

Tangible win: add one cancellable wait seam between retry attempts, then test its order without time.Sleep.

Waiting is behavior—name it

A fixed time.Sleep inside a retry wrapper makes a unit test slow and creates timing guesses. Instead, the wrapper depends on a small function. Production can provide a timer-backed wait later; the unit test supplies an immediate fake.

type retryWait func(context.Context) error

type getProfile func(context.Context, string) (Profile, error)

func getProfileWithRetryWait(
    ctx context.Context, id string, get getProfile, wait retryWait,
) (Profile, error) {
    profile, err := get(ctx, id) // attempt 1
    if err == nil || !retryableDependencyError(err) {
        return profile, err
    }

    if err := wait(ctx); err != nil { // only between attempts
        return Profile{}, err
    }
    return get(ctx, id) // attempt 2
}
Contract: wait runs exactly once only after a retryable first failure. If it returns an error—especially ctx.Err()—the second request never begins. It receives the caller’s same context, so cancellation still owns the work.

Test the sequence, not a clock

Use an append-only event list. The fake wait does no waiting; it merely proves the retry wrapper called it in the right place.

func TestRetryWaitsOnceBeforeSecondAttempt(t *testing.T) {
    events := []string{}
    get := func(context.Context, string) (Profile, error) {
        events = append(events, "get")
        if len(events) == 1 { return Profile{}, errors.New("reset") }
        return Profile{ID: "42"}, nil
    }
    wait := func(context.Context) error {
        events = append(events, "wait")
        return nil
    }

    got, err := getProfileWithRetryWait(context.Background(), "42", get, wait)
    if err != nil || got.ID != "42" { t.Fatalf("got %#v, %v", got, err) }
    want := []string{"get", "wait", "get"}
    if len(events) != len(want) { t.Fatalf("events = %v", events) }
    for i := range want {
        if events[i] != want[i] { t.Fatalf("events = %v; want %v", events, want) }
    }
}

This uses only the standard library. Add a second test where wait returns context.Canceled: expect ["get", "wait"] and errors.Is(err, context.Canceled).

Do not overbuild the delay

  • This seam does not choose a duration, jitter, or number of retries.
  • Do not call wait after a successful first attempt or a non-retryable stop signal.
  • A production wait must observe ctx.Done(); otherwise cancellation can be delayed by a timer.

Quick check

The first get returns a retryable error, then wait(ctx) returns context.Canceled. Which event sequence is correct?
