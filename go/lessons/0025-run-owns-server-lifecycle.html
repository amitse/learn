Make Run own the server lifecycle

You have tested the shutdown contract. Now give one function ownership of the matching lifecycle: serve until shutdown begins, then wait for the server to stop. That makes main small and makes the boundary testable.

One owner, one lifecycle

Starting a server and shutting it down are one operational unit. Put both in Run; callers receive one error that says whether serving or shutdown failed. Server.Serve returns http.ErrServerClosed after Shutdown or Close; that expected result is not a startup failure.

Node / TypeScript
async function run(server: Server) {
  const stopped = once(server, "close")
  await server.listen(8080)
  await stopped
}
Go
func Run(srv *http.Server, ln net.Listener) error {
  err := srv.Serve(ln)
  if errors.Is(err, http.ErrServerClosed) {
    return nil
  }
  return err
}
Ownership rule: the function that calls Serve is responsible for interpreting its expected terminal error. Do not make main or a test remember that special case.

Start serving, then initiate shutdown

Serve blocks, while a signal watcher (or test) must be able to call Shutdown. Start Run in a goroutine; use a buffered channel so its result can be delivered even if the receiver is not ready at that instant.

func TestRunReturnsNilAfterShutdown(t *testing.T) {
    ln, err := net.Listen("tcp", "127.0.0.1:0")
    if err != nil { t.Fatal(err) }

    srv := &http.Server{Handler: http.NewServeMux()}
    done := make(chan error, 1)
    go func() { done <- Run(srv, ln) }()

    ctx, cancel := context.WithTimeout(context.Background(), time.Second)
    defer cancel()
    if err := srv.Shutdown(ctx); err != nil {
        t.Fatalf("Shutdown: %v", err)
    }

    if err := <-done; err != nil {
        t.Fatalf("Run: %v, want nil", err)
    }
}

Read the boundary

1net.Listen(..., ":0") gives the test an isolated listener—the same real-network seam from Lesson 21.

2Run blocks in Serve, so it runs in a goroutine.

3Shutdown closes the listener and makes Serve return http.ErrServerClosed.

4Run translates that expected lifecycle outcome to nil; an unexpected serving error still reaches the caller.

Use the exact sentinel with errors.Is, preserving the error-chain habit from Lesson 8. The behavior of Shutdown and Serve is documented by the standard library.
