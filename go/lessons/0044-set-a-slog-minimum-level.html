Set a slog minimum level

Your lifecycle logs are now JSON. The next operational choice is deliberate noise control: configure one handler so debug records are suppressed in production while INFO, WARN, and ERROR remain visible.

Tangible win

By the end, you can construct a JSON logger with an explicit INFO threshold and write a deterministic test proving that DEBUG does not reach its output.

A handler decides what is enabled

Every slog record has a level. A handler’s Enabled decision determines whether a record is processed. slog.HandlerOptions{Level: slog.LevelInfo} makes the threshold explicit: records at INFO and above are handled; DEBUG is not. The default is also INFO, but stating the choice at the composition boundary documents the deployment policy.

TypeScript / Node mental model

// A logger transport filters below "info"
createLogger({ level: "info", format: json() })

logger.debug("SQL details") // suppressed
logger.info("server started") // emitted

Go

// HandlerOptions filter below INFO
opts := &slog.HandlerOptions{Level: slog.LevelInfo}
logger := slog.New(slog.NewJSONHandler(os.Stderr, opts))

logger.Debug("SQL details") // suppressed
logger.Info("server started") // emitted
Boundary rule: select format and threshold where main assembles the logger. Call sites describe the importance of an event with Debug, Info, Warn, or Error; they should not each decide whether production prints it.

Make the threshold visible

func newLogger(out io.Writer) *slog.Logger {
    opts := &slog.HandlerOptions{
        Level: slog.LevelInfo,
    }
    return slog.New(slog.NewJSONHandler(out, opts))
}

// main:
logger := newLogger(os.Stderr)
logger.Info("HTTP server starting",
    slog.String("version", moduleVersion()),
    slog.String("revision", revisionForLog()),
)

LevelInfo is appropriate for the lifecycle events already established: startup, clean stop, and unexpected failure. It does not mean every future diagnostic must be INFO. Use DEBUG for high-volume detail that helps during investigation but would create routine production noise.

Test the policy through output

Do not test HandlerOptions fields in isolation. Capture the logger’s output and assert the externally observable policy: an INFO record appears; a DEBUG record does not.

func TestLoggerSuppressesDebugAtInfoThreshold(t *testing.T) {
    var out bytes.Buffer
    logger := newLogger(&out)

    logger.Debug("diagnostic detail")
    logger.Info("HTTP server starting")

    text := out.String()
    if strings.Contains(text, "diagnostic detail") {
        t.Fatal("DEBUG record was emitted")
    }
    if !strings.Contains(text, "HTTP server starting") {
        t.Fatal("INFO record was not emitted")
    }
}

This test has no timestamp assertion, server, listener, or environment dependency. It tests exactly the operational contract you own: the threshold controls which records reach the selected handler.

Do this now

  1. Put opts := &slog.HandlerOptions{Level: slog.LevelInfo} beside your JSON handler construction.
  2. Keep existing lifecycle events at their current levels and attributes.
  3. Add the output-based test above; run go test ./....
  4. Only lower the threshold to slog.LevelDebug for a temporary local investigation or an intentionally configured non-production environment.
