database/sql + pgx: Connecting Postgres

Replace your in-memory store with a real Postgres database.

Goal: By the end of this lesson you will be able to open a Postgres connection with pgx, run a QueryRow + Exec, and swap your in-memory task store for a real DB layer — without touching your handler or middleware code.

1 · Why pgx, and how it relates to database/sql

Go's standard library ships database/sql — a generic DB abstraction that works with any driver. pgx/v5 is the most widely-used Postgres driver. It can be used two ways:

  • pgx native API — more Postgres-specific features, slightly more ergonomic for pure-Postgres projects
  • pgx as a database/sql driver — standard interface, easier to swap drivers later, familiar to any Go dev

This lesson uses pgx as a database/sql driver so the concepts transfer to MySQL, SQLite, etc.

→ pkg.go.dev/database/sql  ·  pgx as database/sql driver

2 · TypeScript → Go mental model

TypeScript (node-postgres / pg)
import { Pool } from 'pg'

const pool = new Pool({
  connectionString: process.env.DATABASE_URL
})

// query
const { rows } = await pool.query(
  'SELECT id, title FROM tasks WHERE id=$1',
  [id]
)
const task = rows[0]

// insert
await pool.query(
  'INSERT INTO tasks(title) VALUES($1)',
  [title]
)
Go (database/sql + pgx)
import (
  "database/sql"
  _ "github.com/jackc/pgx/v5/stdlib"
)

db, _ := sql.Open("pgx", os.Getenv("DATABASE_URL"))

// query one row
var t Task
err := db.QueryRowContext(ctx,
  "SELECT id, title FROM tasks WHERE id=$1",
  id,
).Scan(&t.ID, &t.Title)

// insert
_, err = db.ExecContext(ctx,
  "INSERT INTO tasks(title) VALUES($1)",
  title,
)

Key differences:

  • No await — Go is blocking/synchronous within a goroutine. The HTTP server runs each request in its own goroutine automatically.
  • .Scan() instead of rows[0] — you scan columns directly into Go variables/struct fields.
  • Blank import _ "…/stdlib" — registers the pgx driver with database/sql as a side effect. The underscore means "import for side effects only".

3 · Setup: add pgx to your module

  1. Add the dependency 
    go get github.com/jackc/pgx/v5
    This adds pgx to go.mod and downloads it to the module cache.
  2. Create a DATABASE_URL env var
    pgx accepts standard Postgres connection strings: 
    # .env (use godotenv or export directly)
DATABASE_URL=postgres://user:pass@localhost:5432/mydb?sslmode=disable
  3. Open + ping in main.go 
    import (
  "database/sql"
  "log"
  "os"
  _ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
  db, err := sql.Open("pgx", os.Getenv("DATABASE_URL"))
  if err != nil {
    log.Fatal(err)
  }
  if err := db.Ping(); err != nil {
    log.Fatal("cannot reach database:", err)
  }
  // pass db to your store / handlers...
}
    Tip
    sql.Open does NOT open a connection — it just validates the driver name and DSN format. db.Ping() is what actually dials the database. Always ping on startup.

4 · Replacing the in-memory store with a DB store

Remember the capstone store from Lesson 13? It held tasks in a map[string]Task with a sync.RWMutex. The swap is surgical — handlers don't change at all because the store satisfies the same interface. 

// internal/store/store.go  (was: in-memory map)
// NOW: Postgres-backed

package store

import (
  "context"
  "database/sql"
)

type Store struct {
  db *sql.DB
}

func New(db *sql.DB) *Store {
  return &Store{db: db}
}

func (s *Store) GetTask(ctx context.Context, id string) (Task, error) {
  var t Task
  err := s.db.QueryRowContext(ctx,
    "SELECT id, title, done FROM tasks WHERE id = $1",
    id,
  ).Scan(&t.ID, &t.Title, &t.Done)
  if err == sql.ErrNoRows {
    return t, ErrNotFound
  }
  return t, err
}

func (s *Store) CreateTask(ctx context.Context, title string) (Task, error) {
  var t Task
  err := s.db.QueryRowContext(ctx,
    "INSERT INTO tasks(title, done) VALUES($1, false) RETURNING id, title, done",
    title,
  ).Scan(&t.ID, &t.Title, &t.Done)
  return t, err
}
Tip: RETURNING
Postgres's RETURNING clause lets you get the inserted row back in one round-trip — no need for a second SELECT. This is idiomatic Go-Postgres style. Docs →
sql.ErrNoRows
When a QueryRow finds nothing, Scan() returns sql.ErrNoRows. Always check for this sentinel error so handlers can return a proper 404 instead of a 500.

5 · Querying multiple rows

QueryRowContext handles one row. For a list of tasks use QueryContext and iterate with rows.Next():

TypeScript
const { rows } = await pool.query(
  'SELECT id, title, done FROM tasks'
)
return rows // Task[]
Go
rows, err := s.db.QueryContext(ctx,
  "SELECT id, title, done FROM tasks")
if err != nil { return nil, err }
defer rows.Close() // always!

var tasks []Task
for rows.Next() {
  var t Task
  if err := rows.Scan(&t.ID, &t.Title, &t.Done); err != nil {
    return nil, err
  }
  tasks = append(tasks, t)
}
return tasks, rows.Err()
Two places errors can hide
After iterating, always check rows.Err() — a network error mid-stream won't appear until after the loop. And always defer rows.Close() to release the connection back to the pool.

6 · Connection pool settings

sql.DB is a connection pool, not a single connection. Tune it once in main.go: 

db.SetMaxOpenConns(25)         // max connections to Postgres
db.SetMaxIdleConns(5)          // keep 5 idle, ready to reuse
db.SetConnMaxLifetime(5 * time.Minute) // avoid stale connections
