Test Run drains an active request

Your lifecycle owner now separates “stop” from its drain deadline. Prove that contract without time.Sleep: start one request, cancel Run, show it has not returned, then release the handler.

The contract to prove

http.Server.Shutdown closes listeners and waits for active connections to become idle. The test should establish the exact event order with channels—not hope that the scheduler has caught up.

Node / TypeScript
const started = deferred<void>()
const release = deferred<void>()
app.get("/hold", async () => {
  started.resolve()
  await release.promise
  return "ok"
})
// abort, prove close still pending,
// then release.resolve()
Go
started := make(chan struct{})
release := make(chan struct{})
handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    close(started)
    <-release
    w.WriteHeader(http.StatusOK)
})
// cancel, prove Run is pending,
// then close(release)
One concept: a coordination channel is evidence, not a delay. started proves the handler is active; release gives the test control over when it can finish.

A deterministic lifecycle test

func TestRunDrainsActiveRequest(t *testing.T) {
    started := make(chan struct{})
    release := make(chan struct{})
    srv := &http.Server{Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        close(started)                 // evidence: this request is active
        <-release                       // test controls completion
        w.WriteHeader(http.StatusOK)
    })}

    ln, err := net.Listen("tcp", "127.0.0.1:0")
    if err != nil { t.Fatal(err) }
    t.Cleanup(func() { _ = ln.Close() })

    stop, cancel := context.WithCancel(context.Background())
    t.Cleanup(cancel)
    runDone := make(chan error, 1)
    go func() { runDone <- Run(stop, srv, ln, time.Second) }()

    go func() { _, _ = http.Get("http://" + ln.Addr().String()) }()
    <-started                           // never cancel before the request is active

    cancel()                            // begin graceful shutdown
    select {
    case err := <-runDone:
        t.Fatalf("Run returned before request drained: %v", err)
    default:                             // correct: Run is still waiting
    }

    close(release)                       // now the handler may finish
    if err := <-runDone; err != nil {
        t.Fatalf("Run() = %v, want nil", err)
    }
}

1Start Run and put its one terminal result in a buffered channel.

2Launch the request, then receive from started. Now cancellation cannot race ahead of handler entry.

3Cancel and use a non-blocking select. If Run has already returned, it violated the drain contract.

4Release the handler and require Run to return nil.

Why no timeout in the assertion?

A timeout turns a correctness check into a timing bet: a busy CI worker can make a correct program look broken, and a too-short delay can let a broken program look fine. The handler’s release channel gives an unambiguous boundary instead. Keep the production grace period (time.Second here) as a safety guard; it is not the test’s synchronization mechanism.

// This asks “has Run returned right now?”—it never waits.
select {
case err := <-runDone:
    t.Fatalf("returned too early: %v", err)
default:
    // Run is correctly waiting for the active handler.
}
