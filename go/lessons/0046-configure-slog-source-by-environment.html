Configure slog source by environment

Lesson 45 made source locations available. Now make that choice at your existing configuration boundary: a local run can include caller details, while production can deliberately keep its JSON lean.

Tangible win

You will carry one boolean from validated configuration into logger construction, then test both output policies without touching os.Getenv or starting an HTTP server.

One policy, one input

AddSource belongs to slog.HandlerOptions, but whether it is enabled is deployment policy. That makes it configuration—not a decision for a request handler or a logger.Info call. Give it a clear, explicit setting such as LOG_SOURCE.

TypeScript / Node

type Config = { logSource: boolean };

const logger = createLogger({
  format: json(),
  includeCaller: config.logSource,
});

Go

type Config struct {
    LogSource bool
}

func newLogger(out io.Writer, cfg Config) *slog.Logger {
    opts := &slog.HandlerOptions{
        Level: slog.LevelInfo,
        AddSource: cfg.LogSource,
    }
    return slog.New(slog.NewJSONHandler(out, opts))
}
Boundary rule: raw environment text is untrusted input. Parse it once into Config; pass the typed value onward. The logger should not read LOG_SOURCE itself.

Parse strictly, fail early

Use strconv.ParseBool. It accepts documented spellings such as true, false, 1, and 0; a typo produces an error instead of quietly changing observability. Below, absence means the conservative default: no source locations.

func loadLogSource(lookup Lookup) (bool, error) {
    raw, ok := lookup("LOG_SOURCE")
    if !ok || raw == "" {
        return false, nil
    }
    enabled, err := strconv.ParseBool(raw)
    if err != nil {
        return false, fmt.Errorf("parse LOG_SOURCE: %w", err)
    }
    return enabled, nil
}

// During config loading:
source, err := loadLogSource(lookup)
if err != nil { return Config{}, err }
cfg.LogSource = source

This reuses the injected Lookup seam from Lesson 19. A map-backed lookup makes every policy case deterministic.

Test configuration and rendered output separately

First table-test parsing: missing → false, "true" → true, invalid → error. Then test the logger’s observable result with an in-memory buffer. Do not test a specific source file or line.

func TestLoggerSourcePolicy(t *testing.T) {
    for _, tt := range []struct {
        name string; enabled bool; wantSource bool
    }{
        {"disabled", false, false},
        {"enabled", true, true},
    } {
        t.Run(tt.name, func(t *testing.T) {
            var out bytes.Buffer
            newLogger(&out, Config{LogSource: tt.enabled}).Info("started")
            var got map[string]any
            if err := json.Unmarshal(out.Bytes(), &got); err != nil { t.Fatal(err) }
            _, hasSource := got["source"]
            if hasSource != tt.wantSource { t.Fatalf("source=%v, want %v", hasSource, tt.wantSource) }
        })
    }
}

Do this now

  1. Add LogSource bool to the application configuration that already owns log level and deployment settings.
  2. Parse LOG_SOURCE through the injected lookup, with false when absent and an error when invalid.
  3. Pass the typed config to your logger constructor and assign AddSource: cfg.LogSource.
  4. Run go test ./.... Decide the production value with the people who use the logs.
