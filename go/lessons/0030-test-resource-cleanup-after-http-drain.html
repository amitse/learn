Test resource cleanup
after HTTP drains

Your server’s shutdown order is now a policy. Prove it with one fake resource: while an in-flight handler is blocked, its dependency must still be open; only after the handler releases may cleanup close it.

The one contract

cancel stop context→listener closes→handler drains→Run returns→resource closes

Lesson 29 placed pool.Close() after Run. This lesson tests that ordering without Postgres. A fake is better here: it exposes exactly the event we care about, so no sleep and no database setup are needed.

Build the smallest observable fake

type fakeResource struct {
    closed chan struct{}
    once   sync.Once
}

func newFakeResource() *fakeResource {
    return &fakeResource{closed: make(chan struct{})}
}

func (r *fakeResource) Close() {
    r.once.Do(func() { close(r.closed) })
}

sync.Once makes cleanup idempotent, like a real pool’s close operation should be. The channel is not production behavior; it is an observation point owned by the test.

Practice: prove the ordering

Assume Run(stop, srv, ln, grace) is the lifecycle owner from lessons 25–28. The application edge calls resource.Close() only after Run returns.

started := make(chan struct{})
release := make(chan struct{})
resource := newFakeResource()

mux.HandleFunc("GET /work", func(w http.ResponseWriter, r *http.Request) {
    close(started)
    <-release                 // keep HTTP work active
    w.WriteHeader(http.StatusNoContent)
})

runDone := make(chan error, 1)
go func() { runDone <- Run(stop, srv, ln, time.Second) }()

// Send a request, then wait until its handler is active.
<-started
cancel()                      // shutdown begins

select {
case <-resource.closed:
    t.Fatal("resource closed before HTTP drained")
default:
    // Correct: active handler can still use the resource.
}

close(release)                // permit handler and Run to finish
if err := <-runDone; err != nil { t.Fatal(err) }
resource.Close()

select {
case <-resource.closed:
    // Correct: cleanup follows the drain.
default:
    t.Fatal("resource was not closed after Run returned")
}
Two assertions, two moments: before releasing the handler, closure is forbidden; after Run returns and cleanup runs, closure is required. The test proves order—not elapsed time.
