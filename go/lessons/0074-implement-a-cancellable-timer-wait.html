Implement a cancellable timer wait

Your retry wrapper already accepts a retryWait. Now supply the small production implementation: wait for a duration or stop immediately when the request context ends.

Tangible win: write a timer-backed retryWait that never makes a canceled request wait out its retry delay.

One race: timer vs. cancellation

A bare time.Sleep(delay) cannot be interrupted. A timer exposes a channel, and select lets the wait return when either the timer fires or ctx.Done() closes.

type retryWait func(context.Context) error

func timerWait(delay time.Duration) retryWait {
    return func(ctx context.Context) error {
        timer := time.NewTimer(delay)
        defer timer.Stop()

        select {
        case <-ctx.Done():
            return ctx.Err()
        case <-timer.C:
            return nil
        }
    }
}
Contract: a timer firing means “the delay completed” and returns nil. A done context means “the caller ended this work” and returns ctx.Err(). The retry wrapper from Lesson 73 then returns that error without making attempt two.

TypeScript mental model

TypeScript / Node

function wait(ms: number, signal: AbortSignal) {
  return new Promise<void>((resolve, reject) => {
    const id = setTimeout(resolve, ms)
    signal.addEventListener("abort", () => {
      clearTimeout(id)
      reject(signal.reason)
    }, { once: true })
  })
}

Go

timer := time.NewTimer(delay)
defer timer.Stop()

select {
case <-ctx.Done():
  return ctx.Err()
case <-timer.C:
  return nil
}

Both versions race a deadline against cancellation. In Go, ctx.Done() is the receive-only channel that closes when the context is canceled or reaches its deadline.

Test the stop path without sleeping

Do not test a one-second wait by waiting a second. Start from an already-canceled context; its Done channel is ready, so this test finishes immediately even though the configured timer is long.

func TestTimerWaitReturnsCancellationImmediately(t *testing.T) {
    ctx, cancel := context.WithCancel(context.Background())
    cancel() // make ctx.Done() ready before invoking the wait

    err := timerWait(time.Hour)(ctx)

    if !errors.Is(err, context.Canceled) {
        t.Fatalf("err = %v; want context.Canceled", err)
    }
}

This verifies the HTTP-server property that matters: once a caller disconnects or its request deadline expires, the retry path can stop instead of holding a goroutine until a backoff timer completes.

Keep policy boundaries intact

  • timerWait implements how one selected delay waits; it does not decide whether an error is retryable.
  • The retry wrapper still owns the order: first call → approved failure → wait → second call.
  • Keep the delay value explicit at composition time, e.g. wait := timerWait(100 * time.Millisecond). Exponential backoff and jitter are later policy choices.
  • defer timer.Stop() releases a still-pending timer when cancellation wins. There is no need to read timer.C after this function returns.
