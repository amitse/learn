Control slog level at runtime

Yesterday’s LOG_LEVEL selects a threshold at startup. When an incident needs temporary detail without restarting a server, use one shared, concurrency-safe level value: slog.LevelVar.

Tangible win

You will wire a LevelVar into a JSON handler, change the threshold while the process is running, and test the observable effect. You will also name its owner—so a useful diagnostic switch does not become an unaudited global.

The one moving part is the threshold

Keep the rule from Lesson 47: log calls report facts at truthful severities. The handler applies deployment policy. LevelVar is an implementation of slog.Leveler whose value can be changed safely while handlers consult it.

TypeScript / Node

const level = { current: "info" };
const logger = createLogger({
  level: () => level.current,
});

// incident control path
level.current = "debug";

Go

var level slog.LevelVar
level.Set(slog.LevelInfo)

handler := slog.NewJSONHandler(out,
  &slog.HandlerOptions{Level: &level})
logger := slog.New(handler)

// incident control path
level.Set(slog.LevelDebug)
Important: pass the same pointer (&level) to HandlerOptions.Level, then call level.Set(...). Passing a plain slog.Level freezes the threshold selected at construction.

Initialize it from your existing typed config

Do not add another environment read. Your configuration boundary already validates LOG_LEVEL into cfg.LogLevel. Use that typed value to establish the initial policy, then make the mutable level an explicit application-owned dependency.

type App struct {
    LogLevel *slog.LevelVar
    Logger   *slog.Logger
}

func newApp(out io.Writer, cfg Config) *App {
    var level slog.LevelVar
    level.Set(cfg.LogLevel) // cfg is already validated

    logger := slog.New(slog.NewJSONHandler(out,
        &slog.HandlerOptions{Level: &level}))
    return &App{LogLevel: &level, Logger: logger}
}

A later admin endpoint, authenticated CLI, or platform control plane can call app.LogLevel.Set(slog.LevelDebug). That control path is separate from request handlers and should have an operational reason, authorization, and an audit event. If you do not have that need, the restart-time LOG_LEVEL policy is simpler.

Prove the live change, not internals

Write an INFO record, lower the shared threshold to DEBUG, then write a DEBUG record. A buffer reveals the contract: the first debug event is absent; the second is present. This avoids inspecting implementation fields or relying on timing.

func TestLevelVarChangesHandlerThreshold(t *testing.T) {
    var out bytes.Buffer
    var level slog.LevelVar
    level.Set(slog.LevelInfo)
    log := slog.New(slog.NewTextHandler(&out,
        &slog.HandlerOptions{Level: &level}))

    log.Debug("before")
    level.Set(slog.LevelDebug)
    log.Debug("after")

    got := out.String()
    if strings.Contains(got, "before") { t.Fatal("debug leaked at INFO") }
    if !strings.Contains(got, "after") { t.Fatal("debug missing after change") }
}
