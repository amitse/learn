Stamp a build version into
lifecycle logs

Lesson 34 gave the application boundary one honest lifecycle message. Make that message operationally useful: each shipped binary should say which build started and stopped, without making build metadata a handler concern.

The one idea: a build can supply a variable

Keep a package-level string variable with a local-development default. At release build time, Go’s linker can replace its value using -ldflags -X. The application boundary reads it when it writes lifecycle logs.

Node / TypeScript
// Often supplied at build time
declare const BUILD_VERSION: string

logger.info({ version: BUILD_VERSION },
  "HTTP server started")
Go
package main

// var, not const: the linker sets it.
var version = "dev"

logger.Printf("HTTP server started version=%s", version)
Boundary rule: version describes the running process, not an HTTP request. Read it in main or the application wrapper—not in every handler and not via context.Context.

Ship it in three small steps

  1. Declare a default. var version = "dev" keeps go run ./cmd/server useful on a laptop.
  2. Log it at the lifecycle boundary. Include the value in process-level start and clean-stop messages.
  3. Override it in the release build. Pass the variable’s package path and name to the linker.
go build \
  -ldflags "-X main.version=v1.4.0" \
  -o api \
  ./cmd/server

The linker’s -X importpath.name=value flag changes a string variable at link time. In this small package main example the name is main.version. A variable in another package needs that package’s full import path instead.

Keep the log and the policy separate

var version = "dev"

func main() {
    logger := log.Default()
    logger.Printf("HTTP server starting version=%s", version)

    if err := runApp(runServer, logger); err != nil {
        logger.Printf("HTTP server failed version=%s err=%v", version, err)
        os.Exit(1)
    }
}

func runApp(run func() error, logger *log.Logger) error {
    if err := run(); err != nil {
        return fmt.Errorf("run HTTP server: %w", err)
    }
    logger.Printf("HTTP server stopped version=%s", version)
    return nil
}

The version makes an event identifiable across deploys; it does not change Lesson 34’s policy. runApp still returns failures, and main still chooses the non-zero exit. If the version must be supplied to a helper, pass it explicitly as a parameter so the dependency remains visible.

Test the default; verify the stamped binary once

A unit test can inject a buffer-backed logger and assert version=dev in the normal lifecycle output. The linker flag is a build concern, so the useful final check is simply to run the produced binary and inspect its startup log.

func TestRunAppLogsDefaultVersion(t *testing.T) {
    var output bytes.Buffer
    logger := log.New(&output, "", 0)

    if err := runApp(func() error { return nil }, logger); err != nil {
        t.Fatalf("runApp() error = %v", err)
    }
    if !strings.Contains(output.String(), "version=dev") {
        t.Fatalf("log = %q; want default version", output.String())
    }
}

For a release artifact, build it with -ldflags, start it, and require its first lifecycle line to contain the expected release or commit identifier. This checks the hand-off between CI and the binary instead of pretending the linker is ordinary application logic.
