Test configuration without touching the environment

Make your configuration loader accept a tiny lookup function. Your production code still reads os.LookupEnv; tests supply a map instead—fast, isolated, and table-driven.

The seam: a function dependency

Lesson 18 put environment parsing at startup. The remaining problem is testing every missing and malformed value without tests changing process-global state. In TypeScript, this is like passing a getEnv dependency instead of mutating process.env.

TypeScript
type Lookup = (key: string) =>
  string | undefined;

function load(lookup: Lookup) {
  const port = lookup("PORT") ?? "8080";
  // validate and return config
}
Go
type Lookup func(string) (string, bool)

func Load(lookup Lookup) (Config, error) {
    port := getenv(lookup, "PORT", "8080")
    // validate and return Config
}

The signature mirrors os.LookupEnv: value plus a boolean that says whether the key exists. A named function type documents the dependency and keeps the production call readable.

Refactor the loader

Only this one concept changes: Load receives how to look up a value. It never knows whether its caller uses the OS, a map, or a test double.

package config

import (
    "fmt"
    "os"
    "strconv"
    "strings"
    "time"
)

type Lookup func(string) (string, bool)

type Config struct {
    Addr            string
    JWTSecret       string
    ShutdownTimeout time.Duration
}

func Load(lookup Lookup) (Config, error) {
    port, err := strconv.Atoi(getenv(lookup, "PORT", "8080"))
    if err != nil || port < 1 || port > 65535 {
        return Config{}, fmt.Errorf("PORT must be 1 through 65535")
    }

    secret, ok := lookup("JWT_SECRET")
    if !ok || strings.TrimSpace(secret) == "" {
        return Config{}, fmt.Errorf("JWT_SECRET is required")
    }

    timeout, err := time.ParseDuration(getenv(lookup, "SHUTDOWN_TIMEOUT", "5s"))
    if err != nil || timeout <= 0 {
        return Config{}, fmt.Errorf("SHUTDOWN_TIMEOUT must be positive")
    }
    return Config{Addr: fmt.Sprintf(":%d", port), JWTSecret: secret, ShutdownTimeout: timeout}, nil
}

func getenv(lookup Lookup, key, fallback string) string {
    if value, ok := lookup(key); ok && value != "" { return value }
    return fallback
}

// Production composition root: the OS is just one implementation.
func FromEnvironment() (Config, error) { return Load(os.LookupEnv) }
Keep the side effect at the edge: FromEnvironment is the only function coupled to the process environment. Handlers and validation deal solely in typed Config values.

Write the table-driven test

A map becomes a lookup function in three lines. Each test case gets its own map, so cases cannot leak state into one another.

func lookup(values map[string]string) Lookup {
    return func(key string) (string, bool) {
        value, ok := values[key]
        return value, ok
    }
}

func TestLoad(t *testing.T) {
    tests := []struct {
        name    string
        env     map[string]string
        wantErr bool
    }{
        {"uses safe defaults", map[string]string{"JWT_SECRET": "dev-secret"}, false},
        {"rejects missing secret", map[string]string{}, true},
        {"rejects bad port", map[string]string{"JWT_SECRET": "x", "PORT": "nope"}, true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            _, err := Load(lookup(tt.env))
            if (err != nil) != tt.wantErr {
                t.Fatalf("Load() error = %v, wantErr %v", err, tt.wantErr)
            }
        })
    }
}

1Arrange: each row declares just the environment values relevant to its scenario.

2Act: pass that row’s map-backed Lookup to Load.

3Assert: compare whether an error occurred. Add field assertions to the successful row as your config grows.

Run only this package with go test ./internal/config, or the whole module with go test ./.... Go discovers _test.go files and TestXxx functions automatically. The testing package documentation describes t.Run subtests and failure methods.
