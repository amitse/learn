Choose a fixed retry delay

Your idempotent profile read may retry once, and its wait is already cancellable. Choose the missing policy: one explicit, bounded delay before that one possible second attempt.

Tangible win: make retry timing a named composition choice—100 * time.Millisecond—rather than a hidden sleep inside your dependency adapter.

Start with the smallest policy that fits

There are at most two attempts in this server path. That means there is at most one gap between them. A fixed delay is the clearest policy: after an approved transient failure, wait one small, documented duration; then make the one allowed retry.

const profileRetryDelay = 100 * time.Millisecond

func newProfileClient(httpClient *http.Client) ProfileClient {
    return ProfileClient{
        do:   httpClient.Do,
        wait: timerWait(profileRetryDelay),
    }
}
Policy contract: this value is a delay between the first retryable failure and the second attempt. It is not a request timeout, a number of attempts, or permission to retry a write.

Why this belongs at composition

The outbound adapter owns making a request and wrapping its transport error. The retry wrapper owns whether to call that safe operation again. The application composition boundary chooses the operational value used by the already-tested timerWait.

// retry wrapper: control flow; it does not choose 100 ms.
func getProfileWithRetry(ctx context.Context, get getProfile, wait retryWait, id string) (Profile, error) {
    profile, err := get(ctx, id)
    if err == nil || !retryableDependencyError(err) {
        return profile, err
    }
    if err := wait(ctx); err != nil {
        return Profile{}, err
    }
    return get(ctx, id) // the one permitted second attempt
}

Keep the duration visible where dependencies are assembled. Do not scatter time.Sleep(100 * time.Millisecond) through handlers, and do not put it inside the transport adapter.

Go

const profileRetryDelay =
  100 * time.Millisecond

client := ProfileClient{
  wait: timerWait(profileRetryDelay),
}

In both versions, production wiring selects the value. The retry algorithm receives a waiting behavior, so its focused tests remain immediate and do not depend on clock time.

Test the policy boundary, not elapsed time

A duration constant does not need a test that waits 100 ms. Test what the retry wrapper promises: it invokes the injected wait exactly once only for a retryable first failure, and it passes the same request context to it.

func TestRetryWaitsOnceBeforeSecondApprovedAttempt(t *testing.T) {
    var events []string
    ctx := context.WithValue(context.Background(), testKey{}, "request-7")
    calls := 0

    get := func(got context.Context, id string) (Profile, error) {
        if got != ctx { t.Fatal("context changed") }
        calls++
        events = append(events, "get")
        if calls == 1 { return Profile{}, errTemporary }
        return Profile{ID: id}, nil
    }
    wait := func(got context.Context) error {
        if got != ctx { t.Fatal("context changed") }
        events = append(events, "wait")
        return nil
    }

    _, err := getProfileWithRetry(ctx, get, wait, "42")
    if err != nil { t.Fatal(err) }
    want := []string{"get", "wait", "get"}
    if len(events) != len(want) {
        t.Fatalf("events = %v; want %v", events, want)
    }
    for i := range want {
        if events[i] != want[i] { t.Fatalf("events = %v; want %v", events, want) }
    }
}

The key point is unchanged: a fake wait verifies policy order without sleeping. timerWait(profileRetryDelay) is tested separately by the already-canceled-context test from Lesson 74.

What this deliberately does not do

  • No exponential backoff: one retry has no sequence to grow.
  • No jitter: add it only when more than one retry or fleet-wide synchronization makes it necessary.
  • No retries after context.Canceled or context.DeadlineExceeded; Lesson 71 excludes them.
  • No hidden change to the dependency timeout. The retry delay consumes part of the caller’s existing request lifetime.
