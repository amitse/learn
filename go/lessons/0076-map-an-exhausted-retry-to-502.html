Map an exhausted retry to 502

Your safe profile read made its one permitted retry, and the dependency still failed. Turn that dependency failure into one safe, stable HTTP response without leaking the transport error.

Tangible win: return 502 Bad Gateway with the existing JSON envelope while preserving the original error for private structured logging.

Classify the boundary, not the error text

This route is acting as a gateway to a profile dependency. If the bounded, approved retry is exhausted, the route cannot complete the client’s request because an upstream service failed. http.StatusBadGateway (502) communicates that gateway/upstream boundary failure; it is more specific than treating it as an internal 500.

Public contract: the client gets {"error":"profile service unavailable"}. The dependency’s concrete cause belongs in the server log, not in JSON.

Keep cause and client response separate

func profileHandler(get getProfile, logger *slog.Logger) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        profile, err := get(r.Context(), r.PathValue("id"))
        if err != nil {
            logger.Error("profile dependency failed",
                slog.Any("error", err),
                slog.String("request_id", RequestIDFromContext(r.Context())),
            )
            writeJSONError(w, http.StatusBadGateway,
                "profile service unavailable")
            return
        }
        writeJSON(w, http.StatusOK, profile)
    }
}

err may be a wrapped transport failure from either attempt. Do not compare its message and do not serialize err.Error(). The wrapper already preserves error identity with %w; logging it as an error attribute retains diagnostic context privately.

writeJSON(w, http.StatusOK, profile)

Both versions retain the real cause for operators and expose a deliberately small API contract. In Go, http.StatusBadGateway avoids a magic number and documents the intended status.

Do not erase cancellation semantics

This mapping is for an exhausted approved dependency retry. It is not a universal mapping for every non-nil error. If the request context has been canceled or its deadline exceeded, the existing retry classifier prevents the second attempt; apply the route’s separate cancellation/deadline policy instead. A 502 says the upstream dependency failed, not that every request failure did.

Test the observable contract

Use the injected operation seam from Lesson 72 to make both attempts return a distinctive private failure. Then assert the status, JSON shape, and no-leak rule—without a network, timer, or string matching against the production logger.

func TestProfileHandler_ExhaustedRetryIsSafe502(t *testing.T) {
    private := errors.New("dial profile.internal: credential=do-not-expose")
    get := func(context.Context, string) (Profile, error) {
        return Profile{}, fmt.Errorf("get profile: %w", private)
    }

    rr := httptest.NewRecorder()
    req := httptest.NewRequest(http.MethodGet, "/profiles/42", nil)
    profileHandler(get, testLogger()).ServeHTTP(rr, req)

    if rr.Code != http.StatusBadGateway { t.Fatalf("status = %d", rr.Code) }
    var got errorResponse
    if err := json.NewDecoder(rr.Body).Decode(&got); err != nil { t.Fatal(err) }
    if got.Error != "profile service unavailable" { t.Fatalf("body = %#v", got) }
    if strings.Contains(rr.Body.String(), private.Error()) { t.Fatal("private cause leaked") }
}

In the real wiring, pass the bounded retry wrapper as get. This focused handler test only owns the HTTP boundary: a dependency failure in, a safe 502 contract out.
