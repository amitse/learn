Test a downstream timeout without sleeping

Cancellation is initiated by a caller. A timeout is a deadline your service chooses for a dependency call. Keep those meanings distinct, then test the timeout deterministically.

Tangible win: write a focused test that makes a blocked downstream request end with an error recognizable as context.DeadlineExceeded.

Give the dependency its own time budget

Derive a deadline context from the handler context, pass it to the outbound request, and defer cancel(). The parent context still wins if the client disconnects first; otherwise the child deadline ends only this dependency wait.

func getProfile(parent context.Context, client *http.Client, url string) error {
    ctx, cancel := context.WithTimeout(parent, 2*time.Second)
    defer cancel()

    req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
    if err != nil { return fmt.Errorf("build profile request: %w", err) }
    _, err = client.Do(req)
    if err != nil { return fmt.Errorf("get profile: %w", err) }
    return nil
}
Important: this is a budget for one outbound operation, not a replacement for the inbound request’s context. Do not start from context.Background() here, or you sever caller cancellation.

Same intention, different idiom

TypeScript / Node

const signal = AbortSignal.any([
  request.signal,
  AbortSignal.timeout(2000),
]);
await fetch(url, { signal });
// timeout rejects; caller abort also wins

Go

ctx, cancel := context.WithTimeout(
  request.Context(), 2*time.Second,
)
defer cancel()
req, _ := http.NewRequestWithContext(
  ctx, http.MethodGet, url, nil,
)
_, err := client.Do(req)

Both compose a request lifetime with a dependency budget. In Go, context.WithTimeout returns a child context and its cleanup function explicitly.

Test the deadline signal, not a duration

Use a deliberately tiny test-only timeout. The fake announces it has started, waits for the request context to finish, then returns that exact context error. The test synchronizes on started; it never guesses with time.Sleep.

func TestGetProfileTimesOut(t *testing.T) {
    started := make(chan struct{})
    client := &http.Client{Transport: roundTripFunc(func(r *http.Request) (*http.Response, error) {
        close(started)
        <-r.Context().Done()
        return nil, r.Context().Err()
    })}

    result := make(chan error, 1)
    go func() { result <- getProfile(context.Background(), client, "https://profiles.example") }()
    <-started

    err := <-result
    if !errors.Is(err, context.DeadlineExceeded) {
        t.Fatalf("error = %v; want a wrapped deadline error", err)
    }
}

For a real codebase, make the timeout a constructor/configuration value so production gets a meaningful budget and the test supplies a short one. Assert error identity with errors.Is, not error text or an exact elapsed time.

Timeout vs cancellation

context.Canceled: the parent was explicitly canceled (for example, client disconnect or shutdown).

context.DeadlineExceeded: a deadline expired. Both can end a request, but retry and HTTP-mapping policy may treat them differently—decide that separately.
